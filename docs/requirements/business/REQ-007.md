# REQ-007 Artifact Categories and Config-Defined Document Types

## User Story

As a project maintainer, I want every artifact to belong to a known category and document commands to come from configuration so that lifecycles are predictable and a new document type needs no code change.

## Description

This group covers the three artifact categories Papyrus manages (backlog, decision, document), the split between configurable and fixed lifecycles — including the document main status and configurable custom statuses — the `document_types` map whose keys are document slugs and CLI command names, the dynamic `papyrus <document-slug>` command family, and the generic content model applied to document types added through configuration. It also fixes how slugs and document status lists are validated so that a configured document type can never shadow a built-in command or introduce an invalid status value.
