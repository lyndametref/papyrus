# REQ-007.002 Configure Document Types

## User Story

As a project maintainer, I want to declare each document type, its document model, and its fields in the configuration file so that I can add, change, or remove a document type without changing Papyrus.

## Group

REQ-007 Artifact Categories and Config-Defined Document Types

## Criticality

Must have

## Description

**Slug.** `document_types` is a map keyed by **document slug**, which is at once the configuration key, the CLI command name (`papyrus <document-slug>`, REQ-007.003), and the type identifier. No separate slug attribute exists.

**The configuration is the only source.** A document type exists if and only if the configuration declares it: an absent slug is absent from commands, views, and search, and no built-in table is consulted after `init` (REQ-005.016).

**Entry keys.** An entry is a mapping with these keys: `model` (`SingleMarkdown`, `GroupedMarkdown`, or `SingleHtmlMockup`; defaults to `SingleMarkdown`); `prefix`, required; `directory`, required and relative to `doc_directory`; `label`, `plural`, `order`, `summary`, `type_alias`; `reference_visibility` (`visible` or `hidden`); `statuses`; `default_status`; `slots`; `api_aliases`; `fields`; `group` and `member` role blocks; and `field_defaults`, a map from field key to the value written on create when that field is absent. `title`, `content`, and `id_shape` are not keys, and there is no `enabled` key: presence in the configuration is the only switch.

**Model shape.** A `SingleMarkdown` entry declares a top-level `fields` sequence and no role block. A `GroupedMarkdown` entry declares `group` and `member` blocks, each with a field sequence and an optional `reference_visibility`, and no top-level `fields`. A `SingleHtmlMockup` entry declares `fields: []`, no role block, and no `statuses` or `default_status`.

**Model-level defaults.** An omitted attribute takes a default derived from the document model, never from a built-in table: `[active, archived]` statuses, no `default_status`, visible reference visibility, a slug-derived label and plural, an `order` after the entries that declare one, and empty summary, aliases, slots, and field defaults. A `SingleMarkdown` entry that omits `fields` declares one optional `description` field under `## Description` with kind `multiline`, while `fields: []` declares none. A role block's omitted `fields` is empty.

**Field items.** A field item accepts `key`, `heading`, `frontmatter_key`, `option`, `label`, `kind`, `required`, `verbs`, `help`, and `values`, and declares at least one of `heading` and `frontmatter_key`. The `key` is required and stable; `option` derives from the key in kebab case when absent; `kind` is `text`, `multiline`, or `list`; `verbs` is a subset of `create` and `edit` defaulting to both; `values` is either a non-empty sequence of allowed strings or the string `record-ids` on a `list` field. A field has no `order` and no `enabled`: sequence position is order everywhere. The reserved keys `id`, `title`, `status`, `labels`, `references`, `created_date`, `updated_date`, `group`, `version`, `kind`, `form`, `path`, and `metadata` may be used neither as a field key nor as a front-matter key. Field keys are unique within a role; the same key may appear in both role blocks. Field semantics — storage locations, required and clearing rules, and sequence order — follow REQ-007.004.

**Unknown attributes.** An attribute that is not a key of the configuration, of an entry, or of a field item is accepted, ignored, and reported as one warning when the configuration loads, and `papyrus check` reports it as a finding. Ignoring it never changes behaviour.

**Invalid values are rejected.** Validation reports every diagnostic in one deterministic pass and never runs a command on a partially valid set (NFR-002.002, REQ-001.004). A diagnostic names the offending location as `document_types.<slug>.<path>`, with keyed or indexed field paths such as `member.fields[story].heading`. Rejected:

- a slug that is empty, contains a character other than an ASCII letter, digit, `-`, or `_`, starts with `-`, or contains whitespace, a control character, or a path separator;
- a slug equal to `init`, `config`, `check`, `task`, `milestone`, `release`, `decision`, `search`, `browser`, `import`, `help`, or `version`, compared case-insensitively, so a document type never shadows a built-in command;
- a required value absent or duplicated: a missing `prefix`, a `prefix` repeated across entries, a missing or absolute `directory`, a `directory` outside the project directory, a repeated directory, or a repeated slug key;
- a `model` value outside the three models, or a model shape violation as described above;
- a status list that is empty, has duplicates, omits `active` or `archived`, or gives a custom status an invalid name; a custom status reusing a reserved value; a `default_status` that is not declared or is `archived`; any `statuses` or `default_status` on a `SingleHtmlMockup` entry;
- a field with an unknown `kind` or `verb`, with neither `heading` nor `frontmatter_key`, with a reserved key, or with a duplicate key within its role; a `values` restriction that is empty, or that is not `record-ids` on a `list` field; a `field_defaults` key that names no declared field.

**Configuration commands.** `papyrus init` writes the selected Seed entries fully expanded (REQ-001.006, REQ-005.016). Adding or removing a document type, and adding, removing, or reordering a field, is a configuration file edit. `papyrus config get|set|unset|list` address configuration leaves by the selector `document_types.<slug>.<path>`, accepting the keyed `member.fields[story].heading` and indexed `group.fields[0].required` forms for the same element; `config set` changes a declared entry, `config unset` of a collection restores the model-level default, and an unknown selector or out-of-range index is rejected in the same diagnostic form. Flat lists (`statuses`, `api_aliases`, `slots`) keep comma syntax and are stored as flow sequences; `fields` is never comma-separated. Every change is validated as the resulting configuration before it is written, and an invalid value is refused with nothing written.

A violating configuration blocks every command with a validation outcome, except three surfaces that stay available for repair: `config get|set|unset|list`, which loads tolerantly and refuses only an invalid write; `init --force`, which replaces the file with the generated configuration; and `check`, which reports the findings (REQ-001.008).

**Adding, removing, and renaming.** Adding an entry adds the document type, its command family, and its browser views. Removing an entry makes the type absent: its former files stay untouched, appear nowhere, and `papyrus check` reports every file that carries managed record front matter but belongs to no configured document type. Renaming a slug is a configuration-only change: no file moves and no identifier is rewritten, so records under the former directory become unmanaged unless the user moves them. No former command name is kept as an alias.

## Acceptance Criteria

- `document_types` is keyed by document slug, and the slug is the command name and the type identifier.
- A document type exists if and only if the configuration declares it; an absent slug is absent from commands, views, and search.
- An entry declares `prefix` and `directory` and accepts `model`, `label`, `plural`, `order`, `summary`, `type_alias`, `reference_visibility`, `statuses`, `default_status`, `slots`, `api_aliases`, `fields`, `group`, `member`, and `field_defaults`.
- `title`, `content`, `id_shape`, and `enabled` are not keys; declaring one produces a warning and no effect.
- An omitted `model` is `SingleMarkdown`, and an unknown model value is rejected.
- A `SingleMarkdown` entry declares a top-level field sequence and no role block; an omitted sequence declares one optional multiline `description` field, and `fields: []` declares none.
- A `GroupedMarkdown` entry declares `group` and `member` blocks and no top-level field sequence.
- A `SingleHtmlMockup` entry declares `fields: []`, no role block, and no `statuses` or `default_status`.
- An omitted attribute takes its model-level default, never a value from a built-in table.
- A field item accepts exactly `key`, `heading`, `frontmatter_key`, `option`, `label`, `kind`, `required`, `verbs`, `help`, and `values`, with `kind` in `text`, `multiline`, or `list` and `verbs` a subset of `create` and `edit`.
- A field declares at least one of `heading` and `frontmatter_key`; a reserved key, a duplicate key within a role, or an invalid `values` restriction is rejected.
- `field_defaults` maps declared field keys only, and its values are written on create when the field is absent.
- An unknown attribute anywhere in the configuration is accepted, ignored with one warning, and reported by `papyrus check`.
- An invalid value of a known attribute is rejected with a `document_types.<slug>.<path>` diagnostic, and validation reports every diagnostic in one deterministic pass.
- A slug follows the stated character rules and does not equal a built-in command name, case-insensitively.
- `prefix` is non-empty and unique, `directory` is relative, inside the project directory, and unique, and a repeated slug key is rejected.
- A status list is non-empty, duplicate-free, and contains `active` and `archived`; `default_status` is a declared status other than `archived`.
- `papyrus init` writes the selected Seed entries fully expanded, and adding a document type or changing a field sequence is a configuration file edit.
- `config get|set|unset|list` use `document_types.<slug>.<path>` selectors, accept keyed and indexed field paths, and reject an unknown selector or out-of-range index.
- Flat lists keep comma syntax and are stored as flow sequences; `fields` is never comma-separated; every write is validated first and an invalid value is refused.
- An invalid configuration blocks every command except the tolerant `config` commands, `init --force`, and `check`.
- Removing an entry leaves its files untouched, shows them nowhere, and makes `papyrus check` report every managed-front-matter file that belongs to no configured type.
- Renaming a slug moves no file and rewrites no identifier, and no former command name is kept as an alias.
