## Findings

### High

**H-1. `config set` and `config unset` on one seed document type drop every other seed type from the effective configuration.**
- Evidence: `src/commands.rs:315-321` materializes only the edited entry when `document_types` is absent, and `materialize_target_entry` writes only `prefix` and `directory` (`src/commands.rs:530-567`). `merge_yaml` replaces `document_types` wholesale (`src/config.rs:2309-2313`), and `resolve_document_types` keeps only the declared slugs (`src/config.rs:1387-1405`). Probe: a file containing only `project_name: X`, then `papyrus config set document_types.req.enabled false`, writes one `req` entry; `config list` then shows 41 `document_types` leaves for `req` and none for `nfr` or `glossary`, and `papyrus nfr --help` prints `error: unrecognized subcommand 'nfr'`. TECH-077 section 6 step 2 says to insert the default `document_types` map, and the start commit c3103fc did materialize the full default map; this change is a regression against both.
- Location: `src/commands.rs:315-321`, `src/commands.rs:530-567`, `src/config.rs:1387-1405`, `src/config.rs:2309-2313`.
- Recommendation: materialize the full minimal seed set (each seed slug with `prefix` and `directory`, plus `enabled: false` only when disabled) before applying the edit, so a present `document_types` map still contains every effective type; or otherwise merge absent seed entries into the effective set. Add an integration test that after one `config set` and one `config unset` the other seed slugs remain effective (`config list` leaves and `papyrus nfr --help`). If wholesale replacement is intentionally kept, TASK-248 AC and TC-114 must be corrected and the destructive behavior documented; that would still exceed the MS-033 AC-7 config-surface scope.

### Medium

**M-1. Mixed diagnostic classes are not aggregated in one pass.**
- Evidence: `validate_candidate` returns as soon as `validate_document_types_declarations` reports anything (`src/commands.rs:87-96`; the strict loader does the same at `src/commands.rs:142-151`). The raw validator covers unknown keys, unknown enums, and role shape (`src/config.rs:1264-1334`) but not reserved field keys, missing `heading`/`frontmatter_key`, or duplicate field keys, which live in `Config::validate` (`src/config.rs:2131-2205`). Probe: a `note` entry with `unknown_key: 1` and a field `key: title` emits only `document_types.note.unknown_key: unknown key`; the reserved `title` is not reported.
- Location: `src/commands.rs:83-98`, `src/config.rs:1264-1334`, `src/config.rs:2131-2205`.
- Recommendation: collect both validators and concatenate in the documented order, or move the reserved/missing/duplicate checks into the raw pass. Add a test with one unknown key, one reserved key, and one duplicate key in the same file and assert all diagnostics.

**M-2. Entry and field type errors do not use the `document_types.<slug>.<path>` diagnostic form.**
- Evidence: `yaml_serde::from_value` errors are mapped verbatim (`src/commands.rs:93-94`, `src/commands.rs:148-149`), and the raw validator does not check scalar/list types (`src/config.rs:1264-1334`). Probes: `config set document_types.req.order abc` returns `invalid type: string "abc", expected u32`; `config set document_types.req.slots bogus` returns `invalid type: string "bogus", expected a sequence`.
- Location: `src/commands.rs:93-94`, `src/commands.rs:148-149`, `src/config.rs:1264-1334`.
- Recommendation: validate entry scalar and list types in the raw pass (`order` as a non-negative integer, `enabled` as boolean, `statuses` as a sequence of strings, `slots` as a sequence of `{key,label}` strings) and emit the selector path; or map serde errors to the edited selector. Add tests for each type failure.

**M-3. Field vocabulary is not validated for selector-safe and CLI-safe grammar.**
- Evidence: `validate_field_specs` checks reserved keys, empty keys, missing storage, and duplicate keys only (`src/config.rs:2131-2171`); it does not validate `key` grammar, `option` grammar or uniqueness, the `## ` heading prefix, or `required` versus `verbs`. `field_options` derives the long name with `key.replace('_', "-")` (`src/registry.rs:2508-2511`), not kebab case. Probe: `key: a.b` validates, and `config list` prints `document_types.note.fields[a.b].heading`, but `config get 'document_types.note.fields[a.b].heading'` returns `invalid key` (exit 4). A numeric key such as `0` is read as an index, and two fields with `option: same` build a registry with duplicate long options.
- Location: `src/config.rs:2131-2171`, `src/registry.rs:2505-2527`.
- Recommendation: validate `key` as a selector-safe and CLI-safe token (for example `[a-z0-9_-]+`, not all digits), validate `option` (non-empty, no leading `--`, no whitespace, unique within a role), require a `## ` heading prefix, reject `required: true` without `create` in `verbs`, and derive options with a real kebab-case function. Add a test that every leaf emitted by `config list` resolves with `config get`, plus duplicate-option and malformed-heading tests.

**M-4. User-defined document-type defaults are absent from the effective configuration surface.**
- Evidence: `resolve_document_types` leaves a user-defined entry exactly as declared and defers decision-33 defaults to the registry (`src/config.rs:1399-1401`); `Config::flattened` prints only present values (`src/config.rs:1842-1934`). Probe: for a user-defined `note` entry, `config get document_types.note.statuses` returns `document_types.note.statuses: selector did not resolve` even though the registry resolves `[active, archived]`.
- Location: `src/config.rs:1387-1405`, `src/config.rs:1842-1934`.
- Recommendation: project `user_defined_entry` defaults into the value used by `config list` and `config get` without writing them to the file, or teach flattened output and selector resolution to fall back to the decision-33 defaults. Add tests for default statuses, order, reference visibility, slots, and `api_aliases` of a user-defined slug.

**M-5. Declared `slots` are not validated, and seed slots are not yet the runtime source.**
- Evidence: `Slot` is deserialized (`src/config.rs:256-261`) but `Config::validate` performs no slot check (`src/config.rs:1658-1799`). The browser still reads `routes::list_slots` from the static `PRESENTATION` table (`src/browser/list.rs:88`, `src/browser/routes.rs:376`), so descriptor and seed slots do not drive list rendering yet. Probe: a user-defined entry with two `slots` both using `key: id` loads and `note list` exits 0.
- Location: `src/config.rs:256-261`, `src/config.rs:1658-1799`, `src/browser/list.rs:88`, `src/browser/routes.rs:376`.
- Recommendation: validate slots (non-empty key and label, no structural key `id`/`title`/`status`/`created`/`updated`/`actions`, no other reserved field key except `group` for a grouped seed type, no repeats) in `Config::validate`. Add a test that seed slots equal `routes::PRESENTATION` until MS-035 switches the browser to descriptor slots, then delete the document entries from `PRESENTATION`.

**M-6. The descriptor-equivalence oracle is self-referential for prefix, directory, enabled, and statuses.**
- Evidence: `expected_document` takes `prefix`, `directory`, `enabled`, `statuses`, and `default_status` from the same effective `cfg` entry (`tests/descriptor_equivalence.rs:485-491`), and `assert_registry_projects` compares a projection of that cfg (`tests/descriptor_equivalence.rs:619-638`). A fill or replace bug that mutates the effective entry moves both sides. The oracle is independent for model, ID shape, verbs, and role field tuples; those assertions are meaningful.
- Location: `tests/descriptor_equivalence.rs:439-502`, `tests/descriptor_equivalence.rs:619-638`.
- Recommendation: hard-code per-fixture expected prefix/directory/enabled/statuses/default status values, or check in a pre-refactor projection snapshot taken at c3103fc, while keeping the independent model/roles/verbs oracle. Add a negative test that mutates one effective field and expects the equivalence check to fail.

### Low

**L-1. HTML-metadata status validation is keyed on the slug literal `ui-mockup` instead of the document model.**
- Evidence: `validate_doc_entry_statuses` sets `let ui_mockup = slug == "ui-mockup"` (`src/config.rs:2029`) and reuses it for `default_status` (`src/config.rs:2085`).
- Location: `src/config.rs:2029`, `src/config.rs:2085`.
- Recommendation: use `DocumentModel::for_slug(slug) == DocumentModel::SingleHtmlMockup` (or the resolved status model) and add a test that a non-mockup type with custom statuses still validates.

**L-2. Two implementations of ADR-036 decision 32 can diverge for role blocks.**
- Evidence: the YAML path `fill_entry_from_seed` recursively fills `group` and `member` roles (`src/config.rs:1351-1380`), while the typed path `merge_entry` replaces the whole role block (`src/config.rs:1005-1027`). A directly constructed `Config` with `group: { fields: [...] }` loses the seed `reference_visibility: hidden`, while the same YAML file keeps it.
- Location: `src/config.rs:1005-1027`, `src/config.rs:1351-1380`, `src/config.rs:1034-1044`.
- Recommendation: make `resolved_document_entry` merge role fields and visibility independently, or use one resolution path; add a test comparing `load_effective_config` with a directly constructed `Config` for a partial group block.

**L-3. Transitional per-type schema and verb builders remain, so options and verbs have two sources of truth.**
- Evidence: `document_schema` still matches eleven slug literals (`src/registry.rs:2463-2477`) and the per-type verb builders remain (`src/registry.rs:613-1950`); `document_descriptor` keeps the transitional `schema` (`src/registry.rs:2549-2553`). `TypeDescriptor::verb_specs` returns `schema.verbs` rather than the field-derived options (`src/registry.rs:256-260`), so the `field_options` path is not yet the command surface.
- Location: `src/registry.rs:256-260`, `src/registry.rs:613-1950`, `src/registry.rs:2463-2491`, `src/registry.rs:2549-2553`.
- Recommendation: this is documented transitional debt for MS-034, not a behavioural defect in MS-033. MS-034 must delete `document_schema`, the per-type document verb builders, and the document `TypedSchema`/`TypedHandler` use, build `verb_specs` from `field_options`, and add a guard test that fails if either returns.

**L-4. The new `config set` integration test is vacuous about the other seed types.**
- Evidence: `tests/nested_config_cli.rs:283-300` asserts only the written file and `req.statuses`; it never asserts that `nfr` or any other seed type remains effective, so it passes with H-1.
- Location: `tests/nested_config_cli.rs:283-300`.
- Recommendation: assert `config list` contains `document_types.nfr` and `papyrus nfr --help` succeeds after the set; repeat for `config unset`.

**L-5. The read-path guard is narrow and substring-based.**
- Evidence: `src/record/mod.rs:44-56` scans only `src/record/*.rs` and `src/browser/records.rs`. `production_source` cuts at the first `#[cfg(test)]`, so an early test module can hide later production lines, and the forbidden list is literal substrings (for example, `ArtifactRegistry::build` with spacing would pass). Other read modules (`src/document.rs`, `src/requirement.rs`, `src/rule.rs`, and the typed handlers) are not scanned, although their signatures now require `&Config` and `&ArtifactRegistry`.
- Location: `src/record/mod.rs:44-95`.
- Recommendation: broaden the guard to every `src/*.rs` read module and normalize whitespace before matching; add a planted-violation test in an unscanned read module path.

**L-6. `config set` and `config unset` accept bracket selectors that their YAML mutators do not implement.**
- Evidence: `valid_config_selector` accepts `slots[0]`, and `config list` prints `document_types.req.slots[0].key`, but `yaml_set` and `yaml_unset` split only on `.` (`src/config.rs:2343-2405`). Probe: `config set document_types.req.slots[0].key bogus` creates a literal `slots[0]` mapping key and fails with `document_types.req.slots[0]: unknown key`.
- Location: `src/commands.rs:279-323`, `src/config.rs:2343-2405`.
- Recommendation: either implement indexed selectors for set/unset or reject bracketed selectors for those commands with a clear validation message; add round-trip coverage for every `config list` leaf category.

**L-7. A grouped document's single record descriptor is built from member fields only.**
- Evidence: `document_record` selects `member.fields` for every grouped type (`src/registry.rs:2683-2705`) and ignores `group.fields`. Seed `req` and `nfr` roles are identical today, so there is no current behaviour change.
- Location: `src/registry.rs:2683-2718`.
- Recommendation: carry role-specific record facts or build per-role descriptors before divergent role sequences are allowed (ADR-036 decision 27); add a test with different group and member field sets.

**L-8. The browser reloads configuration per request against a startup registry.**
- Evidence: `ServerState.registry` is fixed at startup (`src/browser/mod.rs:131-138`), while `ServerState::config()` reloads `papyrus.config.yml` on every request (`src/browser/mod.rs:155-157`); `error_response` falls back to `Config::default()` on failure (`src/browser/mod.rs:469`). This is not a per-record construction, but a config edit or an invalid config can pair a new config with an old registry.
- Location: `src/browser/mod.rs:131-157`, `src/browser/mod.rs:468-470`.
- Recommendation: this is deferred to MS-036, but the serving snapshot must pair config and registry or reload both behind the allowed mtime cache; add a test that an edit between requests cannot pair a new config with an old registry.

## Verdict

**corrections required**

The seed table, derivation, fill/replace precedence, descriptor ownership, and byte-preserving write path are substantially correct and the reported suite, clippy, and fmt evidence was reproduced. H-1 is a user-visible regression that removes ten document types after one ordinary configuration command and contradicts TASK-248 AC and TC-114. M-1 to M-3 are explicit diagnostic-contract gaps, M-4 is a full-effective-configuration gap, M-5 leaves the ADR-041 slot contract unenforced, and M-6 weakens the AC-1 equivalence proof. The low findings are structural debt and test-quality gaps, with owners assigned by the corrections below.

## Corrections

1. **H-1** blocks TASK-248 AC "leaves the other seed types effective from the seed" and TC-114, and exceeds the MS-033 AC-7 config-surface scope. Required: fix the materialization so one `config set` or `config unset` does not remove other seed types, and add the cross-type regression test (L-4). This is not a records change and does not need a new ADR.
2. **M-1, M-2, M-3** block TASK-248 AC "one aggregated pass" and the `document_types.<slug>.<path>` diagnostic contract (TASK-252 AC-3, TECH-077 sections 1, 3, and 8). Required: aggregate both validators, add type validation with paths, and validate the field vocabulary and selector-safe key grammar.
3. **M-4** blocks TASK-248 AC "full effective configuration" and REQ-001.002 for user-defined slugs. Required: expose decision-33 defaults through `config list`/`config get` without writing them.
4. **M-5** blocks ADR-041 decision 8 and leaves MS-035 with an invalid-slot acceptance hole. Required: validate declared slots and cross-check seed slots against the static presentation table until MS-035 removes it.
5. **M-6** blocks the strength of the TASK-251 AC-1 evidence, not production behaviour. Required: replace the self-referential expectations for prefix/directory/enabled/statuses with independent fixture facts or a checked-in c3103fc snapshot.
6. **L-1 to L-8** are low-severity structural or test-quality corrections; L-3 and L-8 are explicitly owned by MS-034 and MS-036. The orchestrator must assign each accepted finding an owner and a follow-up task; none is a blocker.
