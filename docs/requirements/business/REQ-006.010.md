# REQ-006.010 Present Record References as Links

## User Story

As a project contributor, I want every reference to another record to be clickable so that I can follow it and return with the browser back button.

## Group

REQ-006 Local Web Interface

## Criticality

Should have

## Description

Every reference the browser renders to another Papyrus record is a hyperlink, whatever its role: a task's dependencies and milestone, a release's milestones, a milestone's release and tasks, a record's `references`, a member record's owning group, a mockup's task and specifications, and the items of any declared list-valued field whose values are record identifiers. The rule follows the reference itself, not the field that carries it, so a newly declared field whose values are record identifiers is linked without a browser change.

Activating a link opens the referenced record's view, and the browser back button returns to the originating page. A reference that does not resolve to an existing record is rendered as plain text with no error. Links are generated locally and require no network access.

The rule applies to the browser only; command-line output continues to print reference values as text (REQ-006.004).

## Acceptance Criteria

- Every rendered reference to an existing Papyrus record is a hyperlink.
- The rule covers task dependencies, task milestone, release milestones, milestone release, `references` values, a member record's owning group, and a mockup's task and specification references.
- The rule covers the items of any declared list-valued field whose values are record identifiers.
- Activating a link opens the referenced record's view, and the back button returns to the originating page.
- A reference that does not resolve to an existing record is rendered as plain text and raises no error.
- Links are generated locally and require no network access.
- CLI output continues to print reference values as text.
