# REQ-005.016 Provide the Seed

## User Story

As a project maintainer, I want `init` to offer the built-in document types so that I can choose which ones my project configures.

## Group

REQ-005 Project Documentation Management

## Criticality

Must have

## Description

**What the Seed is.** The Seed is the built-in list of document types that the `init` walkthrough offers for selection (GLO-022, REQ-001.006). It is a convenience template: it exists to spare the user from writing common document types by hand.

**Lifecycle.** The walkthrough presents the Seed during `init`. A selected entry is written into `papyrus.config.yml` fully expanded — document model, field sequence, identifier prefix, directory, status set, reference visibility, list slots, and field defaults. An unselected entry is not written at all. A run without an interactive terminal writes every entry.

**After `init` the Seed is irrelevant.** No command, view, search, validation, or default resolution reads it. The project configuration is the only source of document types (REQ-007.002), and a document type exists if and only if the configuration declares it. There is no `enabled` key: presence in the configuration is the only switch, and removing an entry removes the type.

**Content.** The Seed contains exactly these entries; the criticality column is a requirement attribute of the built-in type, not a configuration key.

**One definition.** This requirement is the only definition of the built-in document types. No other requirement, table, or module defines a built-in type, its fields, or its defaults.

## Acceptance Criteria

- The Seed is the list of document types offered by the `init` walkthrough, and `init` is the only command that reads it.
- A selected entry is written into `papyrus.config.yml` fully expanded: document model, field sequence, identifier prefix, directory, status set, reference visibility, list slots, and field defaults.
- An unselected entry is not written.
- A run without an interactive terminal writes every Seed entry.
- The Seed is not read by any command, view, search, validation, or default resolution after `init`.
- The project configuration is the only source of document types, and a document type exists if and only if the configuration declares it.
- There is no `enabled` key; presence in the configuration is the only switch, and removing an entry removes the type.
- The Seed contains exactly the eleven entries of the table above, with the document model, prefix, field sequence, reference visibility, and statuses stated there.
- The criticality column is a requirement attribute of the built-in type and is not a configuration key.
- A field is optional unless the table marks it required, and each field's declared verbs, kind, and option are as stated.
- No other requirement, table, or module defines a built-in document type.
