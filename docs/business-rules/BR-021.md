# BR-021 Unclaimed Document Records Are Reported by check

## Description
`papyrus check` reports as a finding every Markdown file that carries managed record metadata but belongs to no document type declared in the configuration.

A file carries managed record metadata when its front matter has an `id` plus the `created_date` and `updated_date` keys that Papyrus writes. The file is unclaimed when the document type that produced that identifier is absent from `document_types`, for example after the type's entry was removed from the configuration.

The finding names the file and states that no configured document type claims it. `check` never moves, rewrites, or deletes the file, and `--fix` never repairs this finding; it remains reported until the file is moved, deleted, or its document type is declared again.

Exceptions: a Markdown file without managed record metadata is prose and is not reported. A record stored under a configured type's `archived/` subfolder still belongs to that type and is not reported.

Example: `test-report` is removed from `document_types` and twelve files remain under `docs/test-reports/`. `papyrus check` reports twelve unclaimed-record findings, one per file, and changes nothing.

## Rationale
Based on REQ-001.008 and REQ-007.002: the configuration is the only source of document types, so removing an entry leaves records nobody manages; check must surface them so the user is not left with silently orphaned files.

## Applicability
Every papyrus check run, over every Markdown file in the project corpus. It never applies to prose Markdown without managed record metadata and never changes a file.

## Requirements
- REQ-001.008
- REQ-007.002
