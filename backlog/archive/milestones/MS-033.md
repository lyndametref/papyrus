## Description
Internal checkpoint of one deliverable: model and configuration layer only.

Goal: replace the 'static descriptor assumption and per-type hard-coded schemas with owned, seed-derived descriptors and a validated config-declared field schema, per ADR-A and ADR-0019. Old configuration files must load identically.

Target model: DocumentModel with SingleMarkdown, GroupedMarkdown, SingleHtmlMockup; FieldSpec items with key, heading, frontmatter_key, option, label, kind (text|multiline|list), required, verbs ([create, edit] default), help; no order or enabled; sequence position is order for body and CLI options; heading and/or frontmatter_key required; general front-matter keys reserved; field keys unique per role; reserved field keys id, title, status, labels, references, created_date, updated_date, group.

Acceptance criteria:
AC-1 Old and new configuration parse to the same effective document-type descriptor set.
AC-2 Scalars fill from the seed, collections (fields, group.fields, member.fields, statuses) replace, prefix and directory are never filled, an absent slug stays absent.
AC-3 Every unknown key or enum is rejected with a document_types.<slug>.<path> diagnostic.
AC-4 The emitter round-trips quoted "## ..." headings, renders mapping sequences as block sequences, and keeps flat string lists inline.
AC-5 No read path builds a config or registry per record.
AC-6 Unit tests cover reserved field keys, seed-only GroupedMarkdown and SingleHtmlMockup, user-defined types defaulting to SingleMarkdown, and immutable group membership.
AC-7 No CLI or browser behavior changes in this milestone.
