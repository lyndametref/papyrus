## AUD-041 finding 1 (medium) verification
Resolved. With backlog/milestones mode 0555, `papyrus milestone archive MS-001` exits 1, prints "Permission denied (os error 13)", removes the destination it wrote, and leaves exactly one file, backlog/milestones/MS-001.md, byte-identical with status open; backlog/archive/milestones is left without the record and a retry after restoring permissions succeeds. The doc comment at 778-788 no longer claims an atomic move.

Rollback can itself fail. Rollback is `let _ = fs::remove_file(&dest)` (861); its error is discarded. If the rollback unlink fails (destination directory turned read-only, Windows sharing/AV lock, immutable attribute, filesystem error), both copies remain, the command still exits 1, and the error text names only the source unlink failure with no path or indication that an archived copy survived; the doc comment's "so only the source copy remains" is then untrue. See finding 9.

Concurrency residue (finding 10): the `dest.exists()` guard is advisory and write_atomic renames over an existing target. Two concurrent archives that both pass the exists() check can have the later process's rollback delete the destination the earlier process kept, leaving zero copies.

Regression test: archive_rolls_back_destination_when_source_unlink_fails exercises the real code path on this host (chmod 0555 on the active folder, probe confirms permissions are enforced, exit 1 asserted, destination absent, source bytes unchanged, retry yields exactly one copy, PermissionGuard restores mode on drop). Under root or a filesystem without permission enforcement the probe returns early and the test silently passes without exercising the path (finding 6).
