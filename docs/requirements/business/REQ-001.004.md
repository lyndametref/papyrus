# REQ-001.004 Use Common CLI Controls and Outcomes

## User Story

As a Papyrus user or command-line integration, I want consistent common options and exit outcomes so that I can operate the tool and recognize command results.

## Group

REQ-001 Project Setup and CLI Access

## Criticality

Must have

## Description

Papyrus provides global JSON, colour, version, and help options. `--json` applies to every command that produces output, including error output. Colour can also be disabled with `NO_COLOR`. Exit statuses are distinct for success, runtime error, usage error, record not found, and validation or conflict outcomes. An invalid effective configuration is a validation outcome reported before any command work begins, except on the repair surfaces (REQ-001.002, REQ-001.008, REQ-007.002).

## Acceptance Criteria

- `--version` prints the version and exits, and `-h`/`--help` prints help; command help is available as `papyrus <command> --help`.
- `--json` produces machine-readable JSON for output-producing commands, including error output.
- `--no-color` or `NO_COLOR` disables ANSI colour output.
- Success, runtime error, usage error, record not found, and validation or conflict outcomes use exit codes 0, 1, 2, 3, and 4 respectively.
- An invalid effective configuration produces a validation outcome before command dispatch, except for `config get|set|unset|list`, `init --force`, and `check`.
- `papyrus check` runs with an invalid configuration, reports the findings, and exits with code 4 when an error-level finding exists (REQ-001.008).
