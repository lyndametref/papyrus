# REQ-001.001 Initialize a Papyrus Project

## User Story

As a project maintainer, I want to initialize Papyrus in a chosen directory so that the project has its backlog store, documentation structure, and configuration.

## Group

REQ-001 Project Setup and CLI Access

## Criticality

Must have

## Description

The user initializes a project in the current directory or in a directory selected with `--dir`; a directory that does not exist is created. Initialization records the supplied project name in the configuration, creates the backlog store and the documentation structure, and writes `papyrus.config.yml` (REQ-001.006). `--no-git` skips version-control initialization.

The generated configuration contains the document types selected in the initialization walkthrough, each written in full. A run without an interactive terminal writes every Seed entry (REQ-001.006, REQ-005.016, REQ-007.002). Document types can be added, changed, or removed afterwards by editing the configuration.

Initialization is allowed in a non-empty directory, and no file other than `papyrus.config.yml` is ever modified. An existing `papyrus.config.yml` blocks initialization unless `--force` is given; `--force` replaces that file completely with the generated configuration and keeps no value from the previous file.

## Acceptance Criteria

- `papyrus init <NAME>` initializes the current directory and stores `<NAME>` as the project name.
- `papyrus --dir <PATH> init <NAME>` initializes `<PATH>`, creating it when absent.
- Initialization creates the backlog store, the documentation structure, and `papyrus.config.yml`.
- The generated configuration contains the document types selected in the walkthrough, each written in full.
- A run without an interactive terminal writes every Seed entry.
- Initialization succeeds in a non-empty directory, and no pre-existing file other than `papyrus.config.yml` is modified.
- An existing `papyrus.config.yml` without `--force` fails with a conflict outcome and writes nothing.
- An existing `papyrus.config.yml` with `--force` is replaced completely, keeping no previous value.
- `--no-git` suppresses version-control initialization.
- The generated configuration validates successfully.
