# NFR-007.001 Inventory latency at 1,000 records (p95 under 250 ms)

## Group
NFR-007 07 Document Engine Performance

## Description
Papyrus shall serve the document-type inventory page (`/`) with a p95 latency below 250 ms when 1,000 active records exist across the enabled document types.

## Rationale
Per-record configuration loading and per-ID directory rescans made the inventory page take 14.2 s at 382 active records (MS-032). The target keeps the inventory usable at the 1,000-record scale the descriptor-driven engine is designed for. RE-010 D11 keeps the mtime config and registry cache that removes the repeated per-record work; ADR-037 defines that snapshot.

## Reference Hardware
4 vCPU, 8 GiB RAM, SSD, Linux, one server process, loopback HTTP, release build with LTO and strip.

## Measurement Method
- Corpus: 1,000 generated active records across the enabled document types, including at least one GroupedMarkdown type with a 200-member group and one SingleHtmlMockup type with 50 records.
- Load: 10 warm-up requests, then 100 measured sequential requests to `/` against one running server.
- Reported: p50 and p95 latency as observed by the server.
- Excluded: the first request after a cold start, and any request that triggers a configuration reload.

## Verification Method
Run the MS-032 benchmark harness with the corpus and load above on the reference hardware and compare the reported p95 with 250 ms. Record the harness command, the corpus definition, and the result with the measurement.
