## Findings
1. low | `show_references` is a public field and `ListPlan` derives `Default`, so a `ListPlan` built outside `for_descriptor` silently defaults to hiding references. Today the only production construction is `for_descriptor`, so this is a latent invariant, not a defect. | src/browser/list.rs:24-35, 153 | Make the field private with a getter, or default it to `true`, or carry the content model and resolve visibility inside `render`, so an unset plan cannot hide a Typed family's references. Owner: rust-dev.
2. low | The normative `ListPlan` sketch in TECH-074 §5.1 still lists five fields and omits `show_references`, while the implementation adds a sixth public field. The prose states the visibility rule, so the contract is behaviourally correct but not literally reflected in the struct sketch. | docs/specifications/technical/TECH-074.md:256-262; src/browser/list.rs:31-35 | Update the sketch (or move the rule fully into `render`) so code and the published shared-list contract agree. Owner: tech-writer/rust-dev.
3. low | TC-061 names task rows among the Typed families that keep references, but `/?type=task` is the backlog board with no shared-list rows and the replay deliberately skips the task family. No test asserts task references. | docs/test-cases/TC-061.md:26-29; tests/list_characterization_replay.rs:337-372, 528-531 | Correct TC-061 to exclude the task family (or define a board reference expectation); the task board is unchanged. Owner: test-manager.
4. low | TC-063 says "some [glossary terms] carrying references", but `t182_03_glossary_landing_page_display_is_unchanged` creates two terms with a label and no references, so the "no reference list is added" assertion is never exercised with a reference present. | tests/browser_config_types_cli.rs:1074-1120; docs/test-cases/TC-063.md:26-30 | Add `--reference` to one glossary term and keep the same assertions. The note helper could be expressed through the generic helper. | tests/browser_config_types_cli.rs:56-77 | Define one helper (or a shared `insert_document_type`) and keep `add_note` as a thin call.
