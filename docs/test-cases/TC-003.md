## Scenario: Task files with unquoted @assignee entries parse and retain full metadata after correction

GIVEN corrected task files with quoted assignee entries exist under `backlog/tasks/` (for example TASK-144 and TASK-145)
WHEN the user runs `papyrus task view <imported-id>` for each affected task
  AND runs `papyrus task list`
THEN both files parse without falling back to default values
  AND `task view` reports `title`, `status`, `assignee`, `milestone`, labels, and dependencies for each task
  AND `task list` shows each task's real title rather than its ID
