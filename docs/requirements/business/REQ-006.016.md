# REQ-006.016 Present a Uniform List View Across Record Types

## User Story

As a project contributor, I want every record list view to use one shared layout so that browsing, scanning, and acting on records is consistent across the project.

## Group

REQ-006 Search and Local Web Interface

## Criticality

Should have

## Description

Every browser list view — tasks, milestones, releases, decisions, and every document type — uses one shared list layout. The layout fixes the title cell, the row and column structure, and the placement of actions; family-specific content fills declared slots within it rather than replacing it. No record type uses a bespoke list template.

**Row content.** A row shows the record title and its labels in the title cell and the values of the family's declared slots. A list row carries no reference list; references appear only in the single-record view. Slot values come from the type's configuration entry (REQ-007.002).

**Variants.** A `grouped-record` list renders group rows and read-only member rows through the hierarchical row variant in merged group-then-member order (REQ-005.017). The task list and its board variant are governed by REQ-006.013. The glossary landing page is the one deliberate reduced row (REQ-006.011).

**Sorting.** Every column that carries record data is sortable: identifier, title, status, and each declared slot. Activating a column header sorts ascending; activating the same header again reverses the direction; the active column and direction are indicated. Sorting is stable, with identifier ascending as the tie-break. A sort key outside the list's columns is rejected rather than applied. In a `grouped-record` list, member rows sort within their group and group order is unchanged.

Archived records appear in no list (REQ-005.007).

## Acceptance Criteria

- Every browser list view for every record type uses the same shared list layout.
- The title cell, row and column structure, and action placement are consistent across families.
- Family-specific content appears in declared slots of the shared layout, and no family uses a bespoke list template.
- A document row shows the title and labels in the title cell and the type's slot values; it carries no reference list.
- A `grouped-record` list uses the hierarchical row variant in merged group-then-member order, with read-only member rows.
- Every data column is sortable, ascending then descending, with the active column and direction indicated and identifier as the stable tie-break.
- A sort key outside the list's columns is rejected and no list is rendered.
- In a `grouped-record` list, sorting applies to member rows within each group and leaves group order unchanged.
- The glossary landing page remains the one reduced row, per REQ-006.011.
- Archived records appear in no list.
- The layout renders in the supported browsers and requires no network access.
