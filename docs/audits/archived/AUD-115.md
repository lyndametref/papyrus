## Acceptance criteria
- AC-1 (document create/update accept multiline body/content from stdin): PARTIAL - fails for one document content field. Generic and every typed type that declares --description accept stdin (verified: notes, tech-spec, req, nfr, rule, ui-spec, use-case, test-case, test-report), and decision --decision/--context/--consequences accept stdin (TC-040..TC-044 pass). However `papyrus audit create --content -` stores the literal "-" and a two-line `--content` value exits 4; `glossary --definition` with an embedded newline also exits 4 (src/audit.rs, src/glossary.rs untouched). MS-029 AC-1 says document-type "body and content text", and TASK-191 scope names audit and glossary among the document types in scope, so the content coverage is unresolved. Finding 1.
- AC-2 (task/milestone descriptions from stdin): PASS. tc_045..tc_048 pass; manual create/edit preserve line order, internal blank lines, and existing status (ToDo/open).
- AC-3 (identifiers, titles, single-line fields reject embedded newlines): PASS. tc_049..tc_051 pass; manual middle-newline rejects exit 4 for document/task/milestone/decision titles, ids, labels, acceptance criteria, comments, and assignee, with records unchanged. Note: a trailing newline on an id is trimmed by the pre-existing sanitize_name path and accepted; that behavior is unchanged by this change set and a trailing newline is not an embedded newline.
- AC-4 (existing single-line and editor paths unchanged; no new flags): PASS. Literal values go through Text::literal.resolve() -> sanitize_name, identical to the former per-module sanitizers; invalid UTF-8 piped on stdin is never read when the value is literal (tc_052); the --editor path still writes multiline text (tc_053); no flags were added (diff adds only help text).
- AC-5 (automated regression tests for TC-040..TC-054 plus edge cases): PASS. tests/multiline_stdin_cli.rs maps one-to-one to TC-040..TC-054 and adds empty/whitespace stdin, invalid UTF-8, multiple sentinels before read/write, CRLF normalization, no-implicit-stdin, and typed-type coverage; help goldens regenerated and green.
- AC-6 (help documents the stdin path; README consistent): PASS for the implemented accepting set. The exact sentence `Use "-" to read multiline text from standard input.` appears on --description for the generic model, every typed type that declares it, task and milestone create/edit, and on --decision/--context/--consequences for decision create/edit; README manpage entries carry the same sentence plus the generic-type note. Finding 2 records a help-quality regression.
