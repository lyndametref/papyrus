# UI-012 Papyrus Local Browser (Final Cross-Type Navigation and Inventory)

> **Revised (TASK-196, 2026-11-18):** the "Managed artifacts &amp; lifecycles" and "Agent skills &amp; workflows" entries are retired per ADR-034 and TECH-080 (REQ-06.018, RE-005). `GET /lifecycle`, `GET /skills`, and their `?type=` aliases are not served and return 404, and the inventory hub no longer carries their cards. The cross-type navigation, inventory, list, detail, edit, and metadata scope remain current. This specification is `draft` pending re-verification of the retained scope; the current navigation is specified in UI-018.

## View
final-cross-type

## Description
## 1. Purpose and scope

Layout, states, elements, and interactions for the final cross-type browser: one navigation/inventory that exposes all record types consistently, demonstrating front-matter metadata on a representative subset (task, milestone, release, technical specification), plus the managed-artifact lifecycle and agent skills pages that ADR-034 (TASK-196) retired. Reuses the approved MOCK-0001 shell and the approved patterns of MOCK-0010 and MOCK-0011; does not redraw prior per-type CRUD in full. The browser keeps its current editable field set; `created_date` and `updated_date` are read-only. Metadata edits target front matter, not body sections.

## 2. Shared shell

Header (product name, project name, static offline/bind note), persistent left sidebar `nav` "Document types" with entries in final order (Business requirements, Business rules, Audit records, Technical specifications, Non-functional requirements, Backlog, Decisions, Glossary, UI specifications, UI mockups), `main`, footer, one `h1` per page. Selected entry bold + underline + `aria-current="page"`. The header navigation toggle collapses and expands the sidebar on every page; the default is expanded and the choice persists in `papyrus.nav`, with the navigation expanded and usable without JavaScript. CSP/escaping/accessibility baseline as in MOCK-0001.

Represented types (Technical specifications, Backlog) are clickable; other entries remain non-clickable context, consistent with prior mockups. The Managed artifacts &amp; lifecycles and Agent skills &amp; workflows entries are retired per ADR-034 (TASK-196) and no longer exist (UI-018). Deprecated records are not reachable from navigation (OQ-4).

## 4. Inventory hub

A single view listing all record types as cards with illustrative counts. Represented types link to their representative view; other types state they are covered by prior mockups (MOCK-0001..MOCK-0009) and are not clickable here. Serves as the navigation entry point (OQ-2). The hub carries no card for the retired Configuration, Managed artifacts &amp; lifecycles, or Agent skills &amp; workflows surfaces (ADR-034, TASK-196).

## 5. Metadata display

> **Reconciled under TASK-141 (2026-11-15).** List views are no longer a `ul` of rows with a row metadata. Per ADR-0028 decision 2 (as amended 2026-11-15) every list is one shared table with the fixed column order `ID, Title, Status, family slot(s), Created, Updated, Actions`; `Status` is its own column, `Created` is its own column, and labels and references move into the Title cell. Layout: [`browser-shell-and-shared-list-ui.md`](browser-shell-and-shared-list-ui.md); mockup [`mockups/MOCK-0016-browser-shell-and-shared-list-layout-review.html`](mockups/MOCK-0016-browser-shell-and-shared-list-layout-review.html).

- List views render through the one shared list layout: a table with header cells `ID`, `Title`, `Status`, the family slot(s) (e.g. milestone `Release`), `Created`, `Updated`, `Actions`, each header cell carrying `scope="col"`. There is no row metadata and no per-family row shape.
- `Created` and `Updated` are their own columns and show the stored front-matter values read-only. `Status` is the structural status column for every family; a family does not repeat it as a slot.
- Labels and references appear in the `Title` cell, beneath the title link: a tag line with one tag per label and a muted references line with the identifiers; a record with neither shows no tag area. There is no prefix text and no row metadata. They are general front-matter metadata, identical for every family, and are not a family slot.
- The `Actions` cell is last: `View`, then `Edit`, each with a record-specific accessible name (`View {id}`, `Edit {id}`); a family action, where one already exists, follows `Edit`. The milestone family has none.
- Detail view shows a metadata block (`dl`) with: Record ID, Title, Created date, Updated date, Labels, References, plus type-specific keys (Status, Assignee, Milestone, Dependencies, Documentation for tasks; Release for milestones; none extra for releases/technical specifications except general keys).
- Created date and updated date are rendered read-only in detail and edit (clearly marked "(read-only)"); timestamps are ISO-8601 UTC strings as stored.
- Labels and references are shown as tags in view and as a tag add/remove interaction in edit (reusing MOCK-0002).
- Edit form keeps the current editable field set; timestamps are rendered as disabled inputs. A hidden version field supports optimistic concurrency.

## 6. Task edit states

Pristine edit form with read-only timestamps. (Dirty, validation-error, and conflict states are covered in detail by MOCK-0010; only the baseline edit form is shown here as minimal context.)

## 7. Lifecycle page (retired)

> Retired per ADR-034 (TASK-196): the page, its route, and its sidebar entry are removed. The description below is historical and is not implemented.

- One section (`h2`) per fixed record type: Tasks, Milestones, Releases, Decisions, Business requirements, Non-functional requirements, Glossary terms, UI specifications, Technical specifications, UI mockups, Business rules, Audit records.
- Task section states/transitions reflect configured statuses (sample: To Do &rarr; In Progress &rarr; Done; note they come from configuration).
- Other sections use documented lifecycles (Draft &rarr; Approved &rarr; Deprecated/Restored, etc.).
- Backlog.md docs, drafts, and project configuration files are excluded (stated on the page).
- Each section: state names + transitions + one-line description per state.

## 8. Agent skills page (retired)

> Retired per ADR-034 (TASK-196): the page, its route and alias, and its sidebar entry are removed. The description below is historical and is not implemented.

Reuses MOCK-0011: read-only, configuration-parameterized page with a "Configuration in effect" block and grouped, copyable snippet blocks.

## 9. Error pages and responsive/a11y

Reused from MOCK-0001: 404 unknown, 404 deprecated, 400, 405, 415, 500, each with a recovery link to the inventory. 320 CSS px: list and edit views; sidebar toggle first, full-width rows/fields, stacked form actions, annotation legend. Focus order follows document order; every control has a visible label; works without JavaScript.

## 10. Active elements

- Inventory: type cards/links for represented types.
- Sidebar entry links for represented types (active state + `aria-current`).
- List: sidebar entry, Title-cell link, View and Edit row actions.
- View: breadcrumb links, Edit.
- Edit: title input, description textarea, status select, milestone input, label/reference tag add-remove, Save changes, Cancel, hidden version, read-only timestamps.
- 320 px: sidebar toggle.
- Error pages: recovery link.

## 11. Open questions (recommended defaults)

- OQ-1 (scope of views): navigation shell + representative views + cross-type consistency checks, rather than full per-type CRUD (already covered by prior mockups). (Recommended default.)
- OQ-2 (inventory/landing view): yes, a single inventory/landing view listing all record types with counts. (Recommended default.)
- OQ-3 (sidebar ordering): as established in MOCK-0010/0011 (final order listed in section 2). (Recommended default.)
- OQ-4 (deprecated records reachable): no, consistent with prior mockups. (Recommended default.)
- OQ-5 (responsive 320 px coverage): list + edit + lifecycle + skills. (Recommended default.) Lifecycle and skills retired by ADR-034 (TASK-196); retained coverage is list + edit.

## 13. Assumptions

- Metadata is read from YAML front matter (REQ-05.010/011, ADR-0007, ADR-0009); the browser keeps its current editable field set and writes edits back to front matter.
- A save refreshes `updated_date`, preserves other front-matter keys and the body, and never copies metadata into the body.
- Example records are illustrative.
- The version token is a hidden form field; no merge UI is drawn.
- Counts in the inventory are illustrative.
