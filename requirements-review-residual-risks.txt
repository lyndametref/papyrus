GROUP REQ-001 — Project Setup and CLI Access
(reviewed, changes applied)
====================================================================

State after review: 7 active atomics, 1 deprecation. 8,242 -> 5,416 words (-34%).
Active: .001 .002 .003 .004 .005 .006 .008. Archived: .007.

Resolved by the rewrite: init writes the selected Seed entries; "config set" cannot
add a type; `enabled` and seed-minimal entries removed; the false "milestones are
never archived" statement fixed in .005; the seed-only identifier shape replaced by
the configured model; `id_padding` now lives once, in .005.

R41. Exit status now depends on finding severity
    Severity: high (behaviour change)
    REQ-001.008 states that an error-level finding gives exit 4 while warnings alone
    give 0. The previous rule was "exit 4 whenever any finding exists". Commands,
    business rules and test cases that assume any finding fails must adopt severity.

R42. Deliberate deviation from D2 on the "deprecated/" sentence
    Severity: medium
    D2 asked to drop the inert `deprecated/` sentence from REQ-005.007. It was kept:
    without it, files in such a folder have no defined behaviour (they are neither
    archived nor unmanaged). Only the legacy conflict checks and `--fix` legacy
    refusals were removed from REQ-001.008.

R43. Unclaimed-record finding can be noisy
    Severity: medium
    REQ-001.008 reports every file that carries managed metadata but belongs to no
    configured type. Removing a document type on purpose therefore produces findings
    for its former records until they are moved or deleted. This is the intended
    reading of decision 3a-B, but it will surprise a user who removes a type.

R45. The init offer is fixed to the Seed
    Severity: low
    REQ-001.006 offers only task, milestone, release, the decision types and the Seed
    entries. A project that wants its own type at init must add it by editing the
    configuration afterwards. This is deliberate but worth stating in user
    documentation.

R46. `id_padding` change no longer states a re-display rule
    Severity: low
    REQ-001.005 says existing identifiers are never re-padded and the wider number is
    used, but does not say whether a changed `id_padding` changes how existing
    identifiers are displayed. Current reading: identifiers are stored values and
    changing `id_padding` affects only newly allocated numbers.

GROUP REQ-004 — Decision Records
(reviewed, changes applied)
====================================================================

State after review: 3 active atomics. 634 -> 1,718 words (+171%) because the review
also added a status-verb model, frozen content, delete, and archiving.
Active: .001 Manage Decisions, .002 Change Decision Status, .003 Inspect Decisions.

R58. Decision status verbs are new
    Severity: high (product change)
    REQ-004.002 requires `decision accept|reject|deprecate|supersede --by|archive`.
    The CLI exposes only `edit --status` and `edit --superseded-by`, which must be
    removed in favour of the verbs.

R59. `decision delete` is new
    Severity: high (product change)
    There is no delete verb today. REQ-004.001 requires one, allowed only while the
    status is `proposed`.

R60. Content freeze outside `proposed` is new
    Severity: high (product change)
    `decision edit` currently edits any decision. REQ-004.001 requires editing and
    deleting only while `proposed`, and every other state to reject with no write.

R61. "archived" now means two different things
    Severity: medium
    For decisions it is a status value that moves no file; for documents it is a
    storage location. REQ-007.001 and REQ-004.002 state the distinction, but the CLI
    help, business rules, and UI must not conflate them.

R63. Supersession status mismatch
    Severity: high (correctness)
    The implementation stores the `## Status` value "Superseded by ADR-XXX" while the
    requirements say the value is `superseded` and the successor lives in the
    front-matter `superseded_by` key. The implementation must change, or every existing
    decision file carries a value outside the vocabulary.

R64. Archived decisions stay viewable — assumption to confirm
    Severity: medium
    REQ-004.003 states that an archived decision remains viewable by identifier (it
    stays in place and is historical). Documents behave differently: an archived
    document is unreachable. If decisions should instead be unreachable, that
    requirement clause must be inverted.
