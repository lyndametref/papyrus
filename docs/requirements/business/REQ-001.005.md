# REQ-001.005 Assign Stable Record IDs

## User Story

As a project user, I want Papyrus to assign and preserve record identifiers so that records can be referred to consistently.

## Group

REQ-001 Project Setup and CLI Access

## Criticality

Must have

## Description

Papyrus generates record identifiers automatically. An identifier never changes when a record moves between lifecycle states: a task keeps its identifier across archive and restore, and a document, a milestone, or a release keeps its identifier when archived.

**Identifier shape.** A document record's identifier shape follows its type's configured document model (REQ-007.004). A `SingleMarkdown` or `SingleHtmlMockup` record has one plain identifier `<PREFIX>-<NUMBER>`. A `GroupedMarkdown` group has a plain identifier `<PREFIX>-<GROUP>`, and each member has a dotted identifier `<PREFIX>-<GROUP>.<MEMBER>` under the same type prefix (REQ-005.001). `<PREFIX>` is the type's configured `prefix`.

**Padding.** The shared `id_padding` determines the generated numeric width for tasks, milestones, releases, and every document type. It is a whole number from 1 to 6 inclusive, with a default of 3; a value outside that range is rejected when the configuration is validated, with a message that names the permitted range. Padding is a minimum, never a maximum: when a number's digit count exceeds `id_padding` the wider number is used, and it is never truncated and never an error. Existing files are not re-padded and no migration is performed. The display identifier and the stored identifier are the same value.

**Single identifier space.** The Papyrus identifier is the record identity everywhere: in the front-matter `id`, in command input, and in command-line and browser output. Papyrus keeps no second, tool-specific storage identifier and does not translate between identifier spaces, because file-level interoperability with Backlog.md is renounced. Records brought in by the one-way import receive Papyrus identifiers, and no external identifier is accepted as command input.

## Acceptance Criteria

- Creating any managed record assigns it an identifier automatically.
- A task keeps its identifier across archive and restore, and a document, milestone, or release keeps its identifier when archived.
- A `SingleMarkdown` or `SingleHtmlMockup` record has the plain identifier `<PREFIX>-<NUMBER>` using its type's configured prefix.
- A `GroupedMarkdown` group has the plain identifier `<PREFIX>-<GROUP>`, and its members have dotted identifiers `<PREFIX>-<GROUP>.<MEMBER>` under the same type prefix.
- A newly configured `GroupedMarkdown` type produces grouped identifiers, and a newly configured `SingleMarkdown` type produces plain identifiers.
- `id_padding` accepts only whole numbers from 1 to 6 inclusive, defaults to 3, and rejects any other value during configuration validation with a message naming the range.
- `id_padding` governs the numeric width as a minimum; a wider number is used when its digit count exceeds the padding.
- Existing identifiers are never truncated, re-padded, or migrated when `id_padding` changes.
- The display identifier and the stored identifier are the same value.
- The Papyrus identifier is written to the front-matter `id`, is the only accepted command input for that record, and is what command-line and browser output show.
- No external storage identifier is treated as a Papyrus record identity or accepted as command input.
- Records imported by the one-way import receive Papyrus identifiers and no parallel identifier space is created.
