# NFR-007.003 Browser asset caching contract (versioned immutable vendor assets and validated app assets)

## Group
NFR-007 07 Document Engine Performance

## Description
Papyrus shall serve browser assets with the cache classes below, and no other response shall become cacheable, as fixed by RE-010 D12 and ADR-038.

- Immutable vendor assets: every vendored file is served from a versioned URL `/assets/<package>/<asset-version>/<file>` with `Cache-Control: public, max-age=31536000, immutable`, and no `ETag`; a conditional request is answered with the full `200` and is never a `304`.
- Revalidated app assets: `/assets/app.css`, `/assets/app.js`, and `/assets/nav-state.js` are served with `Cache-Control: no-cache` and one strong `ETag`; a `GET` or `HEAD` whose `If-None-Match` matches receives a bodyless `304` carrying the same `ETag` and `Cache-Control` and no `Content-Type` or `Content-Length`; a non-matching or unparseable tag receives the full `200`.
- No-store: every HTML response and every JSON response, including error and not-found responses, carries `Cache-Control: no-store`, no validator, and never a `304`.
- Assets only: the cache class follows the kind of response, never the route; no record-derived response becomes cacheable.
- No compression: no response carries `Content-Encoding` or `Vary`, and no `Accept-Encoding` negotiation is introduced.

This requirement owns the header-level assertions above. ADR-038 fixes the exact header sets, the conditional-request matrix, and the test retargeting that implements them.

## Rationale
With `no-store` on every response, a diagram page re-transferred the 3.57 MB Mermaid bundle on each navigation, and a math page re-transferred the KaTeX stylesheet, script, and fonts (ADR-038). Immutable versioned vendor URLs remove that repeat cost, and revalidation keeps the first-party assets correct without re-downloading them. Keeping HTML and JSON on `no-store` preserves the read-after-write and privacy posture: a record page is never served from a cache.

## Measurement Method
- HTTP header assertions in the integration suite: the immutable vendor `200` set, the revalidated `200` and `304` sets, the no-store set on HTML and JSON, the absence of `Content-Encoding` and `Vary`, and the `404`/`405` matrix are asserted literally as ADR-038 decision 27 defines them.
- Repeat-visit transfer: the MS-032 harness loads a page with a diagram and a page with math twice and records the bytes transferred on the second load.

## Verification Method
Run the header assertions and the repeat-visit measurement above on the reference hardware (4 vCPU, 8 GiB RAM, SSD, Linux, one server process, loopback HTTP, release build with LTO and strip) and confirm that the second load transfers no vendor bytes and that every assertion of ADR-038 decision 27 passes.

## Scope Note
If asset caching were declined, an explicit exclusion recorded in ADR-038 would replace this requirement. ADR-038 is accepted with asset caching, so this requirement stands.
