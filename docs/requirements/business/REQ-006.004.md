# REQ-006.004 Use Front-Matter Metadata in CLI and Browser Views

## User Story

As a project contributor, I want the command line and the browser to show record information from the record metadata so that both present the same values and I do not have to look inside the file.

## Group

REQ-006 Search and Local Web Interface

## Criticality

Must have

## Description

The command line (plain text and JSON) and the browser (list and single-record views) display the same metadata values for the same record. Both surfaces read the record's stored metadata as defined by REQ-005.010 and project the declared fields of the record's type and role as defined by REQ-005.017; neither surface derives a value from the record body when the metadata defines it, and neither renames a stored value for display.

Both surfaces show at least the identifier, the title, the created and updated dates, the labels, the references, and every declared field of the record's type and role. A record's `status` is shown as stored, including a custom status declared for its type, and is identical in the command line and the browser.

**Browser edit form.** The form offers the fixed title control, one control per declared field whose verbs allow edit, the `labels` and `references` controls, and read-only `status`, created and updated dates. `title` is not a field, and `status` is not editable because it is lifecycle- and configuration-owned (REQ-005.011). A save writes each submitted value to the storage locations its field declares and preserves the metadata and content the save does not change. A `SingleHtmlMockup` record carries no YAML front matter: its metadata is read from and written to its HTML metadata comment, and the same parity applies (REQ-005.008).

## Acceptance Criteria

- CLI list and view output, in plain text and JSON, and browser list and view pages show the same metadata values for the same record.
- Both surfaces show the identifier, the title, the created and updated dates, the labels, the references, and every declared field of the record's type and role.
- A record's `status` is shown as stored, including a custom status, and is identical in the CLI and the browser.
- A stored value is displayed verbatim; the view does not rename or map it.
- The browser edit form offers the fixed title control, the fields whose verbs allow edit, `labels`, and `references`, with read-only `status` and dates.
- `title` is not edited through a field control, and `status` is not editable.
- A browser save writes each submitted value to its declared storage locations and preserves the metadata and content the save does not change.
- A `SingleHtmlMockup` record's metadata is read from its HTML metadata comment, and the CLI and browser show the same values.
