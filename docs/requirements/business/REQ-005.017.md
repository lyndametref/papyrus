# REQ-005.017 View and List Document Records

## User Story

As a project contributor, I want to list and open the records of any document type so that I can find documentation and read it in context.

## Group

REQ-005 Project Documentation Management

## Criticality

Must have

## Description

Every document type declared in the project configuration is listable and viewable from the command line and from the browser. This requirement fixes what list rows and record content contain per document model; the shared chrome, layout, and action placement are owned by REQ-006.016 for lists and by the browser UI specification for single-record views.

**List.** A console list shows one line per record carrying the identifier, the title, and the labels. A browser list row uses the shared list layout and carries the title, the labels, and the type's declared slots (REQ-006.016). Neither list carries a reference list; references appear only in the single-record view. Slot content comes from the type's configuration entry (REQ-007.002).

**grouped-record lists.** A list of a `grouped-record` type shows its group records and their members merged: group order first, then member order within each group. Member rows are read-only in the list (REQ-005.001). Each group row is collapsible: it hides or shows only its own member rows, and the list is fully collapsed by default.

**Record View.** For the Markdown models, a single-record view renders one section per declared field in field-sequence order, using the field's name as the section heading; a field with no value contributes no section, except that a required field with no stored value is rendered as an empty section. Field content is rendered from Markdown using the console's advanced formatting capabilities, so headings, emphasis, lists, tables, code, and quotes are formatted for the terminal rather than printed as raw source; `--no-color` disables the styling and the content stays readable. `--json` output is unaffected and carries the values, not the formatting. For `formatted-record`, the view renders the fixed metadata block instead of field sections (REQ-005.008). The References disclosure is present on the single-record view of every model.

**Out of scope in a view.** A record that is unknown, archived, or of a type that is not configured is not viewable: no command and no browser route returns it, and the browser shows the shared not-found page (REQ-005.007).

**Absence from lists.** Archived records appear in no list.

## Acceptance Criteria

- Every configured document type can be listed and viewed from the command line and from the browser.
- A console list shows one line per record with the identifier, the title, and the labels.
- A browser list row uses the shared layout and carries the title, the labels, and the type's declared slots.
- No list carries a reference list.
- A `grouped-record` list shows group records and their members merged in group order, then member order within a group, with member rows read-only.
- A group row is collapsible, hides or shows only its member rows, and starts collapsed.
- A Markdown record view renders one section per declared field in field-sequence order, headed by the field name.
- Field content is rendered from Markdown with the console's advanced formatting capabilities, so headings, emphasis, lists, tables, code, and quotes are formatted rather than printed as raw source.
- `--no-color` disables the console styling, and the content stays readable.
- `--json` output carries the field values and no console formatting.
- A field with no value contributes no section, except a required field with no stored value, which renders as an empty section.
- A `formatted-record` view renders the fixed metadata block instead of field sections.
- The References disclosure is present on the single-record view of every model.
- An unknown record, an archived record, and a record of a type that is not configured are not viewable and produce no list or view output.
- Archived records appear in no list.
- The shared list layout follows REQ-006.016; the single-record layout follows the browser UI specification.
