# REQ-007.003 Dispatch Config-Defined Record Type Commands

## User Story

As a project contributor, I want to run `papyrus <slug>` for any configured record type so that every document type and every decision type is managed with a consistent command family.

## Group

REQ-007 Record Categories and Config-Defined Document Types

## Criticality

Must have

## Description

**One command family per configured record type.** Papyrus exposes a command named by its slug for every record type declared in `document_types` and every record type declared in `decision_types`. The command tree is built from the configuration at startup, so declaring a valid entry is enough to obtain the command and its help line, with no rebuild and no per-type code (REQ-007.002, REQ-004.001, REQ-007.004).

**Document verbs are derived from the document model.** The verb family of a document type is a function of its document model and is never declared in configuration or supplied by a per-type table:

- Every model has the baseline verbs `create`, `list`, `view`, `edit`, `archive`, and `delete`.
- `status <ID> <VALUE>` exists for `simple-record` and `grouped-record` only (REQ-007.001).
- `create-group` and the `--group` option on `create` exist for `grouped-record` only (REQ-005.001).
- A `formatted-record` record has no `status` verb; `edit --status approved` performs its only state transition (REQ-005.008).
- Two types of the same model expose the same verb set and derive their options from their own field sequences.

There is no `deprecate` and no `restore` verb for documents: `archive` replaces `deprecate` and has no inverse (REQ-005.007). `delete` permanently removes a record, archiving an active record first and asking for confirmation unless `--force` is given.

**Decision verbs are fixed.** Every decision type exposes the same fixed verbs `create`, `list`, `view`, `edit`, `accept`, `reject`, `deprecate`, `supersede`, `archive`, and `delete` (REQ-004.001). The decision verb set is not derived from a model and is not configurable. A decision type has no `status` verb: `accept`, `reject`, `deprecate`, and `supersede` each perform one status transition, and no `edit` option sets the status (REQ-004.002). `archive` moves the file and changes no status.

**Shorthand view.** For a document type, when no verb is given and the next argument is a record identifier of the type, `papyrus <slug> <ID>` behaves as `view <ID>`. A token that is neither a verb nor a record identifier of the type is a usage error.

**Field options and the title contract.** For a document type, field options, the title contract, required and clearing rules, `list` and `multiline` handling, `--editor`, `--label`, and `--reference` follow REQ-005.015, applied to the type's field sequence for the record's role. No field option sets `status`: a Markdown-backed record's status is written only by `status` and `archive` (REQ-005.011), and a `formatted-record` state only by `edit --status approved`. Decision commands have fixed options and no field sequence.

**Deterministic help.** Help output for one configuration is identical across runs, machines, working directories, terminal widths, and locales, and contains no absolute path, host name, timestamp, process identifier, or memory address. Configured record types are listed in the order in which their configuration declares them. The root about line, each type's help line and about line, the type order, and each verb's about line are stable for a given configuration; a document type's about line is `Manage <slug> documents.` Per-option help prose and option order come from the field sequence (`name`, `help`, and position), so a field change legitimately changes them.

**Dispatch outcomes.** `papyrus --help` lists every configured slug alongside the built-in commands, and `papyrus <slug> --help` shows the family's verbs with its options. Global options (`--json`, `--dir`, `--config`, `--no-color`) apply to every command in every record category: backlog, document, and decision (REQ-001.004). An unknown slug or a slug that is not configured is a usage error and never falls back to another command. A slug equal to a built-in command name is rejected when the configuration loads (REQ-007.002), so at invocation a slug always resolves to a configured record type. Command outcomes use the common exit codes of REQ-001.004.

## Acceptance Criteria

- Every record type declared in `document_types` or in `decision_types` has a `papyrus <slug>` command, built from the configuration at startup with no rebuild and no per-type code.
- Every document model has the baseline verbs `create`, `list`, `view`, `edit`, `archive`, and `delete`.
- `status` is offered only for `simple-record` and `grouped-record`; a `formatted-record` type has no `status` verb.
- `create-group` and `--group` are offered only for `grouped-record`.
- A `formatted-record` type uses `edit --status approved` for its only state transition.
- The document verb set derives from the document model alone: no configuration key, per-type table, or per-type module declares a verb, and two types of the same model expose the same verbs.
- Every decision type exposes exactly `create`, `list`, `view`, `edit`, `accept`, `reject`, `deprecate`, `supersede`, `archive`, and `delete`, and no `status` verb.
- The decision verb set is fixed: it is not derived from a model and is not declared in configuration.
- Decision status changes use the status verbs, and no `edit` option sets the status.
- No `deprecate` and no `restore` verb exists for documents; `delete` archives an active record first and requires confirmation unless `--force` is given.
- `papyrus <slug> <ID>` on a document type with an identifier argument and no verb behaves as `view <ID>`, and a token that is neither a verb nor an identifier of the type is a usage error.
- Field options, the title contract, required and clearing rules, `list` and `multiline` handling, `--editor`, `--label`, and `--reference` follow REQ-005.015, and no field option sets `status`; a Markdown-backed record's status is written only by `status` and `archive`, and a `formatted-record` state only by `edit --status approved`.
- Decision commands have fixed options and no field sequence.
- Help output is identical across runs, machines, working directories, terminal widths, and locales, and contains no absolute path, host name, timestamp, process identifier, or memory address.
- Configured record types are listed in the order in which the configuration declares them, and the root about line, each help line, the type order, and each verb's about line are stable for a given configuration.
- Per-option help prose and option order come from the field sequence.
- `papyrus --help` lists every configured slug alongside the built-in commands, and `papyrus <slug> --help` lists the family's verbs with its options.
- Global options apply to every command in every record category, and `--json` output includes errors.
- An unknown or unconfigured slug is a usage error and does not execute another command.
- A slug that collides with a built-in command is rejected when the configuration loads and never shadows it.
- Outcomes use the common exit codes of REQ-001.004.
