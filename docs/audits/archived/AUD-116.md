## Acceptance criteria
- AC-1 (document body/content from stdin): NOT CERTIFIABLE as written. The implemented accepting set works: generic document create/edit and every typed type that declares `--description` pass `sanitize::Text` values into the existing sanitize path (tc_040, tc_041, typed tech-spec create/edit); decision create/edit accepts `--decision`, `--context`, and `--consequences` (tc_042..tc_044); `--description=-` and `-d-` were verified manually. However document content fields that do not use `--description` remain single-line: `audit create/edit --content` and `glossary create/edit --definition` store a literal `-` (discarding piped stdin) and reject embedded newlines with exit 4. AC-1 says document-type create/update accept multiline body and content text, and both fields are record body text, so the coverage is unresolved. Finding 1 blocks AC-1 sign-off.
- AC-2 (task/milestone description from stdin): met. task create/edit (tc_045, tc_046) and milestone create/edit (tc_047, tc_048); a manual multiline task edit preserved status and the acceptance-criteria section.
- AC-3 (identifiers/titles/single-line fields reject newlines): met. tc_049 (title), tc_050 (ID, files unchanged), tc_051 (label, labels unchanged), all exit 4. `sanitize_name` and `sanitize_path_string` are unchanged by the diff and still reject C0/DEL/C1 and embedded newlines.
- AC-4 (existing single-line and editor paths unchanged): met. Literal values still go through `sanitize_name` (literal `a/b` rejected, exit 4); tc_052 proves a literal value never reads stdin (invalid UTF-8 on stdin is ignored); tc_053 proves the editor path still writes a multiline body; no new flags were added. One documented exception: the exact single-line value `-` is now the sentinel (assumption recorded in TASK-191).
- AC-5 (automated regression tests): met for the implemented accepting set. 20 end-to-end CLI tests plus sanitizer unit tests; `cargo test` is green apart from the two pre-existing failures above. If AC-1 is extended to audit content or glossary definitions, AC-5 coverage must be extended with them.
- AC-6 (CLI help documents stdin): met for the implemented accepting set. The exact sentence `Use "-" to read multiline text from standard input.` is on every accepting option; tc_054 asserts it for document, req, task, milestone, and decision create/edit; goldens and README updated. Content fields outside the accepting set do not carry the sentence (finding 1). Caveat: finding 4 (help text replacement).
