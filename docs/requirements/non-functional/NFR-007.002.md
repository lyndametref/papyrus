# NFR-007.002 View and edit latency at 1,000 records (p95 under 100 ms)

## Group
NFR-007 07 Document Engine Performance

## Description
Papyrus shall serve a document view page and the corresponding edit page with a p95 latency below 100 ms when 1,000 active records exist.

## Rationale
Viewing a document took 1.8 s at 382 active records (MS-032) because each reference resolution rescanned descriptor directories and re-parsed the match. The target makes view and edit usable at the 1,000-record scale the descriptor-driven engine is designed for. RE-010 D11 and ADR-037 define the snapshot and request-scoped record snapshot that remove the rescans; ADR-038 removes the unrelated vendor-asset transfer from the repeat visit.

## Reference Hardware
4 vCPU, 8 GiB RAM, SSD, Linux, one server process, loopback HTTP, release build with LTO and strip.

## Measurement Method
- Corpus: 1,000 generated active records across the enabled document types, including at least one GroupedMarkdown type with a 200-member group and one SingleHtmlMockup type with 50 records.
- Load: per document model, 10 warm-up requests, then 100 measured sequential requests to a view route and 100 to the corresponding edit route against one running server.
- Coverage: the measured set includes one record with an unresolved reference and one member record of the 200-member group.
- Reported: p50 and p95 latency as observed by the server, for view and for edit.
- Excluded: the first request after a cold start, and any request that triggers a configuration reload.

## Verification Method
Run the MS-032 benchmark harness with the corpus and load above on the reference hardware and compare the reported p95 for view and for edit with 100 ms. Record the harness command, the corpus definition, and the result with the measurement.
