MOCK-021 · Wireframe review

Document-type list reference visibility

Shared browser list rows for config-defined document types (ContentModel::Generic) omit the reference list. Typed and HTML mockup families keep it. Labels stay in the Title cell for every family. Grayscale wireframe only — no visual styling, library, or technology choices.

Ticket

TASK-179 — Design UI for removing the reference list from document-type browser list views

Sources: REQ-006.019 (source RE-006), ADR-035, TECH-074, TECH-076, TECH-068, TECH-045, MOCK-0016 (shared list contract), UI-016 (shared shell); spec UI-019. Milestone MS-028.

Contract applied here: generic document-type list rows render no reference list in any row; typed and HtmlMockup families keep references; labels render for every family. Single-document view, CLI list and view, JSON API, RecordView, and front matter are unchanged.

Web prototype

Notes list (generic: no reference line), Note detail (generic: References section kept), Business Rules list (typed: references kept), and UI Mockups list (HtmlMockup: references kept).

Open web prototype

What changes, and what does not

  • Generic document types (configured in config, e.g. Notes): the reference list is omitted from every list row. It is not collapsed, emptied, or expandable.
  • Typed families (e.g. Business Rules): the reference line stays in the Title cell.
  • HtmlMockup family (UI Mockups): the reference line stays in the Title cell.
  • Labels: stay in the Title cell for every family.
  • Unchanged: single-document view, CLI list and view, JSON API, RecordView, front matter, fixed columns, status filter, row actions, page width, no-JavaScript behaviour, and offline operation.
