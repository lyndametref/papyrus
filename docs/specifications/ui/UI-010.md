# UI-010 Papyrus Local Browser (Front-Matter Metadata and Managed-Artifact Lifecycle)

> **Revised (TASK-196, 2026-11-18):** the managed-artifact lifecycle page in §6 and its "Managed artifacts &amp; lifecycles" sidebar entry are retired per ADR-034 and TECH-080 (REQ-006.018, RE-005). `GET /lifecycle` and `/?type=lifecycle` are not served and return 404; lifecycle documentation now lives outside the browser. The front-matter metadata scope in §§4–5 remains current and unchanged. This specification is `draft` pending re-verification of the retained scope; the current browser navigation is specified in UI-018.

## View
front-matter-and-lifecycle

## Description
## 1. Purpose and scope

Layout, states, elements, and interactions for (A) showing front-matter metadata in the existing list/detail/edit views for managed record types, and (B) a managed-artifact lifecycle page that ADR-034 (TASK-196) retired from the browser. Reuses the approved MOCK-0001 shell and prior per-type mockups (MOCK-0002..MOCK-0009). The browser keeps its current editable field set; `created_date` and `updated_date` are read-only. Metadata edits target front matter, not body sections. A save writes the new value into front matter, preserves the other front-matter fields and the rest of the file, refreshes `updated_date`, and never copies metadata into the body.

## 2. Shared shell

Header (product name, project name, static offline/bind note), persistent left sidebar `nav` "Document types" with entries (Business requirements, Business Rules, Audit Records, Technical Specifications, Non-functional requirements, Backlog, Decisions, Glossary, UI Specifications, UI Mockups), `main`, footer, one `h1` per page. Selected entry bold + underline + `aria-current="page"`. The header navigation toggle collapses and expands the sidebar at every width; it defaults to expanded and the reader's choice persists in `papyrus.nav`.

Prior entries keep their existing pattern: non-clickable except the type being demonstrated. The "Managed artifacts &amp; lifecycles" entry added by this design and its page are retired per ADR-034 (TASK-196); the current shell carries no such entry (UI-018).

The review file inlines the complete wireframe stylesheet and loads no external stylesheet, script, font, image, or network resource.

## 3. Screen map

| Route | Screen | Prototype views |
| --- | --- | --- |
| `GET /?type=backlog` (tasks) | Task list/detail/edit | `list-tasks`, `view-task`, `view-task-after-save`, `edit-task`, `edit-task-dirty`, `edit-task-errors`, `edit-task-conflict` |
| `GET /?type=backlog` (milestones) | Milestone list/detail | `list-milestones`, `view-milestone` |

## 4. Metadata display

- List rows use the shared contract in `browser-shell-ui.md` §3: ID, Title, Status, declared family slot(s), Created, Updated, Actions, with labels and references in the Title cell. There is no separate row metadata.
- Detail view shows a metadata block (`dl`) with: Record ID, Title, Created date, Updated date, Labels, References, plus type-specific keys (Status, Assignee, Milestone, Dependencies, Documentation, Type, Ordinal for tasks; Release for milestones; none extra for releases/technical specifications except general keys).
- Created date and updated date are rendered read-only in detail and edit (clearly marked "(read-only)"); timestamps are ISO-8601 UTC strings as stored.
- Labels and references are shown as tags in view and as a tag add/remove interaction in edit (reusing MOCK-0002).
- Edit form keeps the current editable field set; timestamps are rendered as disabled inputs. A hidden version field supports optimistic concurrency.

## 5. Task edit states

Pristine, dirty ("Unsaved changes"), validation-error (422) with error summary linking to fields, conflict (409) with reload/view actions and a read-only block of unsaved values. At 320 px the layout stacks form actions; the navigation stays expanded by default and the header toggle persists the reader's choice.

## 6. Lifecycle page (retired)

> Retired per ADR-034 (TASK-196): the page, its route, and its sidebar entry are removed. The description below is historical and is not implemented.

- One section (`h2`) per fixed record type: Tasks, Milestones, Releases, Decisions, Business requirements, Non-functional requirements, Glossary terms, UI specifications, Technical specifications, UI mockups, Business rules, Audit records.
- Task section states/transitions reflect configured statuses (sample: To Do &rarr; In Progress &rarr; Done; note they come from configuration).
- Other sections use documented lifecycles (Draft &rarr; Approved &rarr; Deprecated/Restored, etc.).
- Backlog.md docs, drafts, and project configuration files are excluded (stated on the page).
- Each section: state names + transitions + one-line description per state (OQ-6).

## 7. Error pages and responsive/a11y

Reused from MOCK-0001: 404 unknown, 404 deprecated, 400, 405, 415, 500, each with a recovery link. 320 px list and edit form: sidebar toggle first, full-width rows/fields, stacked form actions, annotation legend. Focus order follows document order; every control has a visible label; works without JavaScript.

## 8. Active elements

List: sidebar entry, row links. View: breadcrumb links, Edit. Edit: title input, description textarea, status select, milestone input, label/reference tag add-remove, Save changes, Cancel, hidden version. 320 px: sidebar toggle. The lifecycle sidebar entry is removed per ADR-034 (TASK-196); the retained views have no dependency on it.

## 9. Open questions (resolved defaults)

- OQ-1 (sidebar label/placement): "Managed artifacts &amp; lifecycles" placed at the end of the document-type list. (Recommended default; pending user confirmation.) Retired by ADR-034 (TASK-196).
- OQ-2 (route): `lifecycle` (or `?type=lifecycle`) as a distinct route. (Recommended default.) Retired by ADR-034 (TASK-196); the route is no longer served.
- OQ-3 (scope): metadata demonstrated on a representative subset (task, milestone, release, technical specification); the metadata block applies to every managed record type. (Main scope question.)
- OQ-4 (timestamp format): ISO-8601 UTC string as stored, read-only, possibly with human-readable secondary.
- OQ-5 (labels/references): tags in view; tag add/remove interaction in edit (reuse MOCK-0002).
- OQ-6 (lifecycle depth): state names + transitions + one-line description per state.

## 11. Assumptions

- Metadata is read from YAML front matter (REQ-005.010/011); the browser keeps its current editable field set and writes edits back to front matter.
- A save refreshes `updated_date`, preserves other front-matter keys and the body, and never copies metadata into the body.
- Example records are illustrative.
- The version token is a hidden form field; no merge UI is drawn.
