## Description

Follow-up to **m-19** (Architecture Checkpoint Follow-ups: Mockup Archive and ADR Alignment). The m-19 checkpoint closed the ADR text but left residual milestone drift in code and prose: ADR-0017 constraint 3 and ADR-0023 decision 2 record that milestones have no archive lifecycle and carry `ArchivePolicy::None`, yet the milestone descriptor template, the record layer, REQ-06.013, and the milestone/release specification still describe an archived milestone.

**Scope.** Three corrections, no feature work:
1. TASK-134 - align the milestone descriptor and the record layer with the ADRs: `ArchivePolicy::None` in the registry template, no lifecycle archive location for milestones, legacy reads from `backlog/archive/milestones/` and `milestones/archived/` preserved, import remains the only writer to `backlog/archive/milestones/`, and `relocate_if_archived` no longer auto-moves an `archived` milestone.
2. TASK-135 - rewrite the REQ-06.013 archived-milestone clauses and regenerate the business requirement index.
3. TASK-136 - correct `docs/specifications/milestone-and-release-management.md` to the close-only milestone lifecycle and record the superseded wording.

**Sequencing.** TASK-134 is the code correction; TASK-135 and TASK-136 record the delivered contract after it, matching the m-19 pattern of documents following the authority they describe.

**Boundaries.** No release milestone or release ticket is created; the release vehicle for m-17/m-18/m-19/m-20 remains an owner decision. No user-visible CLI change beyond preventing the invalid auto-archive. Nothing is marked Done by planning.
