# REQ-007.003 Dispatch Config-Defined Document Commands

## User Story

As a project contributor, I want to run `papyrus <document-slug>` for any configured document type so that every type is managed with a consistent command family.

## Group

REQ-007 Record Categories and Config-Defined Document Types

## Criticality

Must have

## Description

**One command family per configured type.** For every document type declared in the configuration, Papyrus exposes a command named by its slug. The command tree is built from the configuration at startup, so declaring a valid entry is enough to obtain the command and its help line, with no rebuild and no per-type code (REQ-007.002, REQ-007.004).

**Verbs derived from the document model.** The verb family is a function of the type's document model and is never declared in configuration or supplied by a per-type table:

- Every model has the baseline verbs `create`, `list`, `view`, `edit`, `archive`, and `delete`.
- `status <ID> <VALUE>` exists for `simple-record` and `grouped-record` only (REQ-007.001).
- `create-group` and the `--group` option on `create` exist for `grouped-record` only (REQ-005.001).
- `supersede` exists for `formatted-record` only (REQ-005.008).
- Two types of the same model expose the same verb set and derive their options from their own field sequences.

There is no `deprecate` and no `restore` verb for documents: `archive` replaces `deprecate` and has no inverse (REQ-005.007). `delete` permanently removes a record, archiving an active record first and asking for confirmation unless `--force` is given.

**Shorthand view.** When no verb is given and the next argument is a record identifier of the type, `papyrus <document-slug> <ID>` behaves as `view <ID>`. A token that is neither a verb nor a record identifier of the type is a usage error.

**Field options and the title contract.** Field options, the title contract, required and clearing rules, `list` and `multiline` handling, `--editor`, `--label`, and `--reference` follow REQ-005.015, applied to the type's field sequence for the record's role. No create, edit, or field option sets `status` (REQ-005.011).

**Deterministic help.** Help output for one configuration is identical across runs, machines, working directories, terminal widths, and locales, and contains no absolute path, host name, timestamp, process identifier, or memory address. Configured document types are listed in the order in which the configuration declares them. The root about line, the per-type line `Manage <slug> documents.`, each type's help line, the type order, and each verb's about line are stable for a given configuration. Per-option help prose and option order come from the field sequence (`label`, `help`, and position), so a field change legitimately changes them.

**Dispatch outcomes.** `papyrus --help` lists every configured slug alongside the built-in commands, and `papyrus <document-slug> --help` shows the model-derived verbs with their generated options. Global options (`--json`, `--dir`, `--config`, `--no-color`) apply to document commands as to any other command (REQ-001.004). An unknown slug or a slug that is not configured is a usage error and never falls back to another command. A slug equal to a built-in command name is rejected when the configuration loads (REQ-007.002), so at invocation a slug always resolves to a document type. Command outcomes use the common exit codes of REQ-001.004.

## Acceptance Criteria

- Every document type declared in the configuration has a `papyrus <document-slug>` command, built from the configuration at startup with no rebuild and no per-type code.
- Every model has the baseline verbs `create`, `list`, `view`, `edit`, `archive`, and `delete`.
- `status` is offered only for `simple-record` and `grouped-record`; a `formatted-record` type has no `status` verb.
- `create-group` and `--group` are offered only for `grouped-record`.
- `supersede` is offered only for `formatted-record`.
- The verb set derives from the document model alone: no configuration key, per-type table, or per-type module declares a verb, and two types of the same model expose the same verbs.
- No `deprecate` and no `restore` verb exists for documents; `delete` archives an active record first and requires confirmation unless `--force` is given.
- `papyrus <document-slug> <ID>` with an identifier argument and no verb behaves as `view <ID>`, and a token that is neither a verb nor an identifier of the type is a usage error.
- Field options, the title contract, required and clearing rules, `list` and `multiline` handling, `--editor`, `--label`, and `--reference` follow REQ-005.015, and no create, edit, or field option sets `status`.
- Help output is identical across runs, machines, working directories, terminal widths, and locales, and contains no absolute path, host name, timestamp, process identifier, or memory address.
- Configured types are listed in the order in which the configuration declares them, and the root about line, the per-type line, each help line, the type order, and each verb's about line are stable for a given configuration.
- Per-option help prose and option order come from the field sequence.
- `papyrus --help` lists every configured slug alongside the built-in commands, and `papyrus <document-slug> --help` lists the model-derived verbs with their generated options.
- Global options apply to document commands, and `--json` output includes errors.
- An unknown or unconfigured slug is a usage error and does not execute another command.
- A slug that collides with a built-in command is rejected when the configuration loads and never shadows it.
- Outcomes use the common exit codes of REQ-001.004.
