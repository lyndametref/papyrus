# TC-179 View and edit latency stays under 100 ms at 1,000 records

## Description
## Scenario: View and edit latency stays under 100 ms at 1,000 records

GIVEN the reference hardware of 4 vCPU, 8 GiB RAM, SSD, Linux, one server process, loopback HTTP, and a release build with LTO and strip
  AND a corpus of 1,000 active records across the enabled document types
  AND the corpus includes a record with an unresolved reference and a member of a 200-member group
WHEN the benchmark harness performs, per document model, 10 warm-up requests and then 100 measured requests to a view route and 100 to the matching edit route
  AND the first request after a cold start and any request that reloads the configuration are excluded
THEN the harness reports p50 and p95 latency for view and for edit
  AND both reported p95 values are below 100 ms
  AND the harness command, corpus definition, and hardware are recorded with the result
