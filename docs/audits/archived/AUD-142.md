## Findings

### High

**B1 - F7 reserved option validation still misses the clap auto help flag; command build panics with exit 101.**
Evidence: with `document_types.tech-spec.fields[0].option: help`, config validation and registry build succeed, then `papyrus --dir <project> tech-spec create T --description d` (also `create --help`) panics in clap: `Long option names must be unique for each argument, but '--help' is in use by both 'custom' and 'help'`, exit 101.
Location: `src/config.rs:92` (`RESERVED_OPTION_NAMES`), `src/registry.rs:1709` (`validate_derived_surface`), `tests/document_engine_corrections.rs:433` (`f7_every_seed_descriptor_builds_its_command_and_help`).
Why it blocks: F7 requires reserved option names to be rejected with exit 4 selector-path diagnostics instead of a panic, and the F7 tree-build regression test is supposed to cover an adversarial config. The current test builds only `Config::default()` descriptors, so it passes without exercising this case.
Recommendation: reserve `help` (and verify any other clap auto flags) or disable the auto help flag for derived commands, reject the case in both config and registry validation, and add a tree/help test from an adversarial config asserting exit 4 rather than 101.

### Medium

**B2 - F15 sentinel joins remain on task, milestone, release and decision edit; a lone bracketed label is silently dropped.**
Evidence: `task edit TASK-001 --label '[]'` writes `labels: []`, while `tech-spec edit TECH-001 --label '[]'` writes `labels:\n  - "[]"`. The same path handles references, documentation, dependencies and assignee joins; milestone, release and decision edit reproduce the `labels: []` result. The `f15_labels_and_references_are_sequences` and `f15_backlog_list_fields_are_sequences` tests cover document create/edit and task create only, so the edit sentinel path is unexercised.
Location: `src/task.rs:1198-1310`, `src/milestone.rs:711-727`, `src/release.rs:486-502`, `src/decision.rs:729-745`; sentinel interpretation at `src/record/frontmatter.rs:390-405` (`is_list_key`, `format_kv`).
Why it blocks: F15 requires the newline-joined sentinel to be gone and labels/references/documentation/dependencies/assignee to be written as `FrontMatterValue::Sequence` on create and edit; the recorded correction claims this is done. The result is a silent create/edit divergence for a legal bracketed label, the exact value class F15 asks to round-trip.
Recommendation: replace the remaining join plus `SetFrontMatter` calls with `SetFrontMatterValue(..., FrontMatterValue::Sequence(...))` in all four edit paths, and extend the F15 tests to task, milestone, release and decision edit with `[]`, single, multiple and empty values.
