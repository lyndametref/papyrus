# RE-001 Backlog.md import did not translate task metadata to Papyrus syntax

## Description
Context: During verification of milestone MS-022 (backlog milestone m-21), `papyrus task list` returned only TASK-144 and TASK-145, and `papyrus task list --milestone MS-022` returned no results even though both task files declare `milestone: MS-022`.

Root cause: Papyrus intentionally does not maintain cross-compatibility with the Backlog.md format. The import from Backlog.md to Papyrus did not translate Backlog.md syntax into Papyrus syntax: assignee entries such as `- @rust-dev` were carried over unquoted, which Papyrus cannot parse as YAML. As a result task front matter parsing fails and `task_from_document` falls back to default values, losing metadata such as milestone, status, labels, and assignee. The list still shows task IDs because the title falls back to the ID.

Investigation: `papyrus task list` scans `backlog/tasks/*.md` and skips files with migration conflicts; TASK-144 and TASK-145 are the only two shown. Their milestone filter cannot match because parsed milestone is None. A Python YAML reproduction confirmed: "found character '@' that cannot start any token".

Open design question: The import path should have translated Backlog.md syntax into Papyrus syntax; it did not. The intended repair is to correct and rerun the import for affected task files, not to add Backlog.md compatibility to Papyrus.
