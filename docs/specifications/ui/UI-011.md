# UI-011 Papyrus Local Browser (Agent Skills and Workflows Page)

> **Retired (TASK-196, 2026-11-18):** the Agent skills and workflows page is removed from the browser per ADR-034 and TECH-080 (REQ-006.018, RE-005). `GET /skills`, its `/?type=skills` alias, and the sidebar entry are gone; both addresses return 404. Skill documentation remains available outside the browser. This specification is retained for history only: it is not implemented and must not be rebuilt without a new decision. The current browser navigation is specified in UI-018. Status: `draft`.

## Description
## 1. Purpose and scope

Retired design for a read-only browser page listing agent skills and workflows for configuring and operating Papyrus; the page was removed from the browser by ADR-034 (TASK-196) and is described here for history only. The page is agent-facing (not end-user) and presents instructions parameterized by the effective `papyrus.conf.yaml` (prefixes, `id_padding`, statuses, enabled document/decision types, directories, paths, date format). It reuses the approved MOCK-0001 shell and the sidebar pattern of MOCK-0010.

## 2. Shared shell

Header (product name, project name, static offline/bind note), persistent left sidebar `nav` "Document types", `main`, footer, one `h1` per page. Selected entry bold + underline + `aria-current="page"`. The header navigation toggle collapses and expands the sidebar on every page; the default is expanded and the choice persists in `papyrus.nav`, with the navigation expanded and usable without JavaScript. CSP/escaping/accessibility baseline as in MOCK-0001.

Sidebar entries (in order): Business requirements, Business rules, Audit records, Technical specifications, Non-functional requirements, Backlog, Decisions, Glossary, UI specifications, UI mockups. The "Managed artifacts &amp; lifecycles" and "Agent skills &amp; workflows" entries added by this design are retired per ADR-034; the current shell carries neither entry (UI-018).

## 3. Screen map

No route is served. `GET /skills`, `GET /?type=skills`, and the responsive skills view were removed per ADR-034 (TASK-196). Error pages follow the shared shell (MOCK-0001) and link back to the inventory (UI-018).

## 4. Page content

- One `h1` "Agent skills and workflows"; subtitle states the page is agent-facing and read-only and that values reflect the effective configuration.
- A "Configuration in effect" block (`dl`) summarizing: task prefix, milestone prefix, release prefix, ID padding (with example), date format, statuses (joined by `&rarr;`), enabled document types, enabled decision types, backlog/decision/doc directories.
- Grouped skill sections (`h2`), each containing skill articles (`h3` title, short description, copyable monospace snippet block, Copy affordance). Groups:
  1. Project setup and init
  2. Backlog, tasks, milestones, releases
  3. Requirements and documentation management
  4. Search
  5. Browser usage
  6. Release and audit workflows
  7. Configuration management
  8. Decisions
- Additional likely groups (glossary, UI specs/mockups, technical specs, business rules) are covered within group 3.

## 5. Content format (OQ-1)

Recommended default: structured sections with per-skill headings, short description, and copyable command/snippet blocks (monospace) that interpolate configured values; each block has a "Copy" affordance as progressive enhancement (no JavaScript required for core content). List-only is the alternative.

## 6. Derived vs static (OQ-2)

Recommended default: template snippets parameterized by effective config values (prefixes, padding, statuses, enabled types, directories) so instructions match the project; static prose for workflow narrative. Fully static snippets are the alternative.

## 7. Active elements

- None. The page, its sidebar entry, its copy affordances, and its 320 px view are removed per ADR-034 (TASK-196); the recovery link now points to the inventory.

## 8. Error pages and responsive/a11y

Reused from MOCK-0001: 404, 400, 403, 405, 415, 500, each with a recovery link to the inventory (UI-018). At 320 px the navigation is expanded above stacked content by default; the header toggle collapses it and the choice persists. Focus order follows document order; every control has a visible label; works without JavaScript; no horizontal scrolling of text.

## 9. Open questions (resolved 2026-11-10)

All open questions resolved to their recommended defaults by explicit user confirmation on 2026-11-10.

- OQ-1 (content format): **resolved** — structured sections with per-skill headings, short descriptions, and copyable command/snippet blocks (monospace) with a Copy affordance; list-only rejected.
- OQ-2 (derived vs static): **resolved** — template snippets parameterized by effective config values (prefixes, `id_padding`, statuses, enabled document/decision types, directories, paths, date format) with static prose for workflow narrative; fully static snippets rejected.
- OQ-3 (sidebar label/placement): **resolved** — label "Agent skills &amp; workflows", placed after "Managed artifacts &amp; lifecycles" (end of document-type list), always present (not gated by `document_types`); retired by ADR-034 (TASK-196).
- OQ-4 (route): **resolved** — `GET /skills` with alias `GET /?type=skills`; retired by ADR-034 (TASK-196), so the route is no longer served.
- OQ-5 (config summary scope): **resolved** — "Configuration in effect" block summarizes all effective keys (task/milestone/release prefixes, `id_padding` with example, date format, statuses, enabled document/decision types, directories).

## 10. Assumptions

- The page is read-only (no forms/edits); it is an agent-facing reference.
- Command snippets are illustrative; exact CLI verbs follow the documented command behavior in BR-001..BR-016.
- The page works offline; no external resources.
- Example records/values are illustrative.
