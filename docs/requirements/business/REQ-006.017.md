# REQ-006.017 Render Math Formulas and Diagrams in the Browser

## User Story

As a project contributor, I want the browser to render math formulas and diagrams embedded in record content so that technical documentation is legible without leaving Papyrus.

## Group

REQ-006 Search and Local Web Interface

## Criticality

Should have

## Description

The local web interface renders math formulas and Mermaid-style diagrams embedded in the curated prose fields that record views display, so that authors can write mathematical notation and diagrams in Markdown prose and readers see rendered output rather than source. Rendering applies to those prose fields only; it introduces no separate record-body view. Rendering is browser-only: CLI output and every other surface show the source text unchanged.

**Input forms.** Math is recognised as display math between `$$` delimiters, inline math between single `$` delimiters, and fenced code blocks whose info string is `math`, `tex`, or `latex`. A literal dollar sign is written as `\$` and is not a delimiter. Diagrams are recognised only as fenced code blocks whose info string is `mermaid`. A fenced `plantuml` block is shown as source text with a note that it is not rendered. Any other fence or delimiter is left as ordinary Markdown. The rendering library is an implementation decision; this requirement fixes the supported input forms and the constraints.

**Constraints.** Rendering works fully offline: all rendering assets are bundled and no network request, external service, or server-side rendering is required. Rendered output conforms to the supported browsers and must not result in arbitrary script execution. Unrenderable input — an unclosed delimiter, an unparseable formula, or an invalid diagram — is shown as source text with a note instead of breaking the page. Any rendering dependency must be open source and permit linking in a GPLv3-or-later application.

## Acceptance Criteria

- Browser record views render `$$…$$` display math and `$…$` inline math in the curated prose fields they display.
- A `\$` sequence renders as a literal dollar sign and is not treated as a delimiter.
- Fenced blocks with the info string `math`, `tex`, or `latex` render as math formulas, and `mermaid` blocks render as diagrams.
- A fenced `plantuml` block is shown as source text with a note that it is not rendered.
- Any other fence info string or delimiter is left as ordinary Markdown source.
- Unrenderable math or diagram input falls back to its source text with a note instead of breaking the page.
- Rendering is limited to the curated prose fields of record views, and no separate record-body view is introduced.
- CLI output and other surfaces show the source text unchanged.
- Rendering requires no network access, and all assets are bundled with the application.
- Rendering works in the supported browsers.
- Any rendering dependency is open source and permits GPLv3-or-later linking.
- Rendered content does not result in arbitrary script execution.
