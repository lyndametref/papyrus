# UI-014 Papyrus Local Browser (Configuration View, Single Record View Layout, and Lifecycle Configuration)

> **Revised (TASK-196, 2026-11-18):** the configuration view in §4 and the lifecycle page in §9 are retired per ADR-034 and TECH-080 (REQ-06.018, RE-005). `GET /config`, `/?type=config`, `POST /config`, `GET /config/edit`, `GET /lifecycle`, `/?type=lifecycle`, and the `Configuration`, `Managed artifacts &amp; lifecycles`, and `Agent skills &amp; workflows` sidebar entries are removed and return 404; configuration editing is CLI-only (`papyrus config`). The single record view layout, header branding, reference links, NFR grouping, and glossary landing scope remain current. This specification is `draft` pending re-verification of the retained scope; the current navigation is specified in UI-018.

## 1. Purpose and scope

Layout, states, elements, and interactions for (A) the configuration view and (G) the lifecycle page per-artifact descriptions and read-only configuration, both retired by ADR-034 (TASK-196), (B) the shared single record view layout, (C) shared header branding, (D) record references as links, (E) NFR grouping under owning groups, and (F) the glossary landing page revisions. Reuses the approved MOCK-0001 shell and prior per-type mockups (MOCK-0002..MOCK-0013) as context only.

## 2. Shared shell and branding

Every page shares one shell: header (product name, project name, static offline/bind note), persistent left sidebar `nav` "Document types", `main`, footer, one `h1`. Shared header branding (§4a): project name renders large and bold; "Papyrus" renders in smaller letters; the "P" mark keeps its current size and styling; project name is the configured project name. The rule applies to every page and is not restated per type.

Sidebar entries are the document types only. The `Configuration`, `Managed artifacts &amp; lifecycles`, and `Agent skills &amp; workflows` entries added by this design are retired per ADR-034 (TASK-196) and no longer exist (UI-018). Selected entry carries `aria-current="page"` plus bold+underline (non-colour cue). The header navigation toggle sits left of the brand on every page with `aria-expanded`/`aria-controls="site-nav"`; the default is expanded and the choice persists in `papyrus.nav`, with the navigation expanded and usable without JavaScript.

## 4. Configuration view (retired)

> Retired per ADR-034 (TASK-196): the view, its route, its aliases, and its sidebar entry are removed. Configuration is edited through `papyrus config` only (CLI). The description below is historical and is not implemented.

- Removed route and sidebar entry: the view was reached from the `Configuration` entry after the document types; both are retired (ADR-034).
- Shows effective configuration values, including built-in defaults, and marks which keys are explicitly set in `papyrus.config.yml` (badge `explicit` vs `default`).
- Editable keys are exactly those `papyrus config set` accepts; same validation and precedence; no key treated as secret; environment values never shown as editable config.
- Folder-key changes relocate through the single relocation routine (REQ-01.002); the browser never moves a folder; every path passes the project-directory boundary check.
- Linked to the lifecycle page for per-artifact read-only configuration; editing was not duplicated there. Both surfaces are retired (ADR-034).
- Table columns: Key, Effective value, Source (explicit/default), Edit action.

## 5. Single record view layout

- Summary card at the beginning shows only ID, created date, updated date. A sub-requirement additionally shows its owning group in the card; nothing else is added.
- Summary card does not show status, milestone, assignee, labels, or references.
- Labels shown as a taglist under the title.
- Dependencies and references appear at the end as native HTML `<details>` disclosure sections, each shown only when the record has at least one such value; work with JavaScript disabled.
- Applies to every managed Markdown record type with a single record view; UI mockup HTML views excluded.

## 6. Record references as links

- Task dependencies, a task's milestone, `references` values, and a sub-requirement's owning group render as hyperlinks when they resolve to a Papyrus record; activating navigates to the referenced record's view.
- Unresolved references render as plain text with no error and no 404.

## 7. NFR grouping

- Non-functional atomic requirements listed under their owning group entry; no trailing catch-all subsection.
- Owning group derived from the requirement ID prefix (`NFR-XX.YYY` → `NFR-XX`); no `Group` field added to files.
- Group heading shows the group record's title; missing group record falls back to the group number (`NFR-04`).
- A group with no atomic requirements renders as a group row with no member rows; the section count note is computed from the rows actually emitted.
- Every atomic requirement appears under exactly one group.

## 8. Glossary landing page

- Omits created and updated dates.
- Labels shown as tags (same taglist as single record view layout).
- No references shown.
- Detail views follow the single record view layout.

## 9. Lifecycle page (retired)

> Retired per ADR-034 (TASK-196): the page, its route, its alias, and its sidebar entry are removed. The description below is historical and is not implemented.

- One section per fixed record type (Tasks, Milestones, Releases, Decisions, Business requirements, Non-functional requirements, Glossary terms, UI specifications, Technical specifications, UI mockups, Business rules, Audit records).
- Each section: curated description, lifecycle sentence, read-only effective configuration (enabled, ID prefix, storage folder; task section also statuses).
- Configuration values were display-only; changes are made through the CLI (`papyrus config`). The page and its configuration link are retired (ADR-034).
- Covered set fixed; not derived from configured document types.
- Subtitle states Backlog.md docs, drafts, and project configuration files are not covered.

## 10. Error pages and responsive/a11y

Reused from MOCK-0001: 404 unknown, 404 deprecated, 400, 405, 415, 500, each with a recovery link. At 320 px the navigation stays expanded above the content by default; the toggle is available and the reader's collapsed choice persists. Content stacks. Focus order follows document order; every control has a visible label; works without JavaScript; landmarks and `aria-current` as in approved packages.

## 11. Active elements

- Single record view: breadcrumb links, Edit button, disclosure summaries for dependencies/references.
- Reference links: task dependencies, milestone, references, owning group.
- NFR grouping: group/requirement links.
- Glossary landing: term links.
- 320 px: sidebar toggle.
- Error pages: recovery link.

## 12. Open questions (recommended defaults)

- OQ-1 (resolved default): sidebar entry labelled `Configuration`, placed after the document types, linking to `/config`. Subject to TASK-87 approval. Retired by ADR-034 (TASK-196); no such entry or route exists.
- OQ-2: whether the configuration view is reached from the sidebar or a header link. Recommended: sidebar, consistent with lifecycle and skills pages. Retired by ADR-034 (TASK-196).
- OQ-3: whether each per-type specification restates the shared single record view layout or only references it. Recommended: reference by section number to avoid drift.
- OQ-4: disclosure sections default open/closed. Recommended: collapsed by default.
- OQ-5: responsive breakpoints and exact 320 px layout details. Recommended: reuse approved responsive patterns.
