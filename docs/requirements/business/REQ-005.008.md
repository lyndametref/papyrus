# REQ-005.008 Manage Formatted Records

## User Story

As a project contributor, I want to maintain formatted records with an HTML body so that design artifacts can be found, reviewed, approved, and archived.

## Group

REQ-005 Project Documentation Management

## Criticality

Must have

## Description

Every document type declared in the project configuration whose document model is `formatted-record` is managed by this requirement. Such a type has one record per plain identifier, its body is HTML, it declares no field sequence, and it carries no YAML front matter: its metadata lives in an HTML metadata comment instead (REQ-005.010).

**Command family.** The verbs are `create`, `list`, `view`, `edit`, `archive`, and `delete`, derived from the document model (REQ-007.003). There is no `status` verb and no `supersede` verb. A `statuses` or `default_status` declaration on such a type is rejected (REQ-007.002).

**Fixed metadata.** The metadata block carries exactly the keys `status` and `references`. They are engine-owned record data read from and written to the HTML metadata comment; neither is a field, a CLI field option, or a configuration key. `status` holds the record state, and `references` is the record's reference list shown read-only.

**States.** The states are exactly `draft` and `approved`. Configuration cannot add, remove, or rename them. A new record starts `draft`. `edit --status approved` performs the `draft` to `approved` transition, and `--status` accepts no other value; a backwards or skipping transition is rejected. Archived is a storage state, not a metadata status: `--status archived` is rejected.

**Create and edit.** `papyrus <slug> create <TITLE>` creates a record; the title is required and follows the contract of REQ-005.015 applied to the HTML metadata. `--reference` is repeatable. `edit` offers the title, the `references` control, and the `--status` option, which accepts only `approved` and only from `draft`; the browser form offers no status control.

**Archive and delete.** Archiving moves the file into the `archive/` subfolder of the type's directory, hides the record from lists, search, and the browser, preserves its identifier, and changes no metadata status (REQ-005.007). A `draft` or `approved` record may be archived. Deletion permanently removes the record, archiving it first when it is not archived, with confirmation and `--force`. There is no restore command and no supersede command.

**Versioning.** Papyrus does not version a record; version control is provided by the project's version-control system.

## Acceptance Criteria

- The requirement applies to every configured document type whose document model is `formatted-record`, and to no other type.
- A record has one plain identifier, an HTML body, no field sequence, and no YAML front matter.
- The command family is `create`, `list`, `view`, `edit`, `archive`, and `delete`; there is no `status` verb and no `supersede` verb.
- A `statuses` or `default_status` declaration on such a type is rejected.
- The metadata keys are exactly `status` and `references`, both read from the HTML metadata comment.
- The states are exactly `draft` and `approved`, and configuration cannot add, remove, or rename a state.
- A new record starts `draft`; a transition to `approved` is accepted, while a backwards or skipping transition is rejected with no write.
- `edit --status approved` moves a `draft` record to `approved`.
- `--status` accepts no value other than `approved`, and `--status archived` is rejected with no write.
- The browser edit form offers no status control.
- Archive moves the file into the `archive/` subfolder, hides the record from lists, search, and the browser, and preserves its identifier, without changing the metadata status.
- A `draft` or `approved` record may be archived.
- Deletion permanently removes the record, archiving it first when it is not archived, with confirmation and `--force`.
- The title follows the title contract of REQ-005.015 and is held in the HTML metadata.
- `create <TITLE>` is rejected with one validation outcome and writes no file when the title is missing.
- `--reference` is repeatable.
- `edit` offers the title, the `references` control, and the `--status` option, which accepts only `approved` from `draft`.
- No command supersedes a formatted record.
- No restore command exists, and Papyrus does not version a record.
