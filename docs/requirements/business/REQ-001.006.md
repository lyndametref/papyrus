# REQ-001.006 Interactive Init Walkthrough at `papyrus init <project_name>`

## User Story

As a project maintainer, I want the initialization to ask which record types I want so that the generated configuration matches the project.

## Group

REQ-001 Project Setup and CLI Access

## Criticality

Should have

## Description

At `papyrus init <NAME>` (also with `--dir` or `PAPYRUS_DIR`), an interactive walkthrough runs before `papyrus.config.yml` is written. It presents the offered record types as a checklist rendered with the terminal formatting: the row under the cursor and the selection state of every row are clearly distinguishable, and the display reflects the current state at all times. Typed token input, such as space-separated names on one line, is not an acceptable presentation, and end of input confirms the current state instead of waiting.

The offered record types are the core record types task, milestone, and release, the two decision-type Seed entries `adr` and `bdr` (REQ-004.001), and the document-type Seed entries (REQ-005.016). One or both decision types may be selected; each selected type becomes its own command family, and a decision type that is not selected at init cannot be added later when only one is configured (REQ-004.001). The core record types are always written, are shown as such, and are never highlighted or toggled, because they are not document types; their prefixes are still prompted. For every selected decision type and document type the walkthrough prompts the identifier prefix and the storage folder, and the shared roots (`backlog_directory`, `decision_directory`, `doc_directory`) are prompted once. Prompts show their default in brackets, and invalid input re-prompts with a hint naming the default.

**What is written.** The Seed is read from the configuration file compiled into the shared core library (REQ-005.016); `init` reads no project seed file. Each selected document type is written into `papyrus.config.yml` in full, and an unselected type is not written at all. A run without an interactive terminal skips the walkthrough and writes every Seed entry in full with the default prefixes and folders, so an unattended run never waits on a prompt and requires no new flag or environment variable.

## Acceptance Criteria

- The walkthrough presents the offered record types as a checklist rendered with the terminal formatting.
- The row under the cursor and the selection state of every row are clearly distinguishable, and the display reflects the current state at all times.
- Typed token input is not accepted as the selection mechanism.
- The offered record types are task, milestone, release, the decision-type Seed entries `adr` and `bdr`, and the document-type Seed entries.
- Task, milestone, and release are always written, are shown as always included, and are never highlighted or toggled; their prefixes are still prompted.
- One or both decision types may be selected; only selected decision types and document types are written, each in full, and unselected types are not written.
- For each selected decision type and document type, its prefix and storage folder are prompted, and each shared root is prompted once.
- Prompts show their default in brackets and accept it with empty input.
- An invalid prefix or folder is rejected and re-prompted with a hint naming the default.
- The configuration written matches the state shown when Enter was pressed.
- A run without an interactive terminal writes every Seed entry, of both families, in full with the default prefixes and folders, without prompting.
- The Seed is read from the configuration file compiled into the shared core library, and `init` reads no project seed file.
- The walkthrough requires no new command-line flag or environment variable.
- `--force` and `--no-git` behave as documented in REQ-001.001.
- The generated configuration validates successfully, including the `id_padding` range (REQ-001.005).
