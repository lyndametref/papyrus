# REQ-001.005 Assign Stable Record IDs

## User Story

As a project user, I want Papyrus to assign and preserve record identifiers so that records can be referred to consistently.

## Group

REQ-001 Project Setup and CLI Access

## Criticality

Must have

## Description

Papyrus generates record IDs automatically. IDs remain stable across archive/restore cycles for tasks only, and across archiving for documents. Milestones are never archived: `papyrus milestone close <id>` moves a milestone from `open` to `closed` in place (REQ-003.001). Releases are likewise never archived; `papyrus release close <id>` moves a release from `planned` to `released` (REQ-003.002).

The ID shape of a document record is determined by its document model and is seed-only. `id_shape` is not a `document_types` key, and a declaration of `id_shape`, `model`, `title`, or `content` is rejected (REQ-007.002, REQ-007.004). A type takes its model from the seed table, and every user-defined type is `SingleMarkdown`; a user-defined type therefore always has a plain ID even when it reuses a seed prefix, directory, or field name.

A `SingleMarkdown` or `SingleHtmlMockup` record has one plain ID `<PREFIX>-<number>`. A `GroupedMarkdown` group has a plain ID `<PREFIX>-<group-sequence>`, and each member record has a dotted ID `<PREFIX>-<group-sequence>.<member-sequence>` under the same type prefix. In both models the type's configured `prefix` supplies `<PREFIX>` and the shared `id_padding` governs the generated numeric width; padding is a minimum, never a maximum, and a wider number is never truncated. Grouped document types keep the dotted hierarchical form documented for them, such as `REQ-<n>.<m>` for business requirements (REQ-005.001) and `NFR-<n>.<m>` for non-functional requirements (REQ-005.002).

Configurable prefixes and padding determine the generated ID format: task, milestone, and release IDs use their configured prefixes and the shared `id_padding`, and a document type's records use that type's `prefix` with the same `id_padding`. The man page gives `TASK-001`, `MS-001`, and `REL-001` as default examples.

Papyrus keeps a single ID space. The Papyrus ID is the record identity everywhere: in the front-matter `id`, in the CLI and browser output, and as command input. Papyrus does not maintain a second, tool-specific storage ID and does not translate between ID spaces, because file-level interoperability with Backlog.md is renounced (NFR-004.004); the on-disk file-name convention is an architecture decision. Records brought into Papyrus by the one-way Backlog.md import script (NFR-004.004) receive Papyrus IDs on import, and no Backlog.md ID is accepted as command input.

The `id_padding` configuration is constrained to 1-6 characters (REQ-001.007). Values outside this range error out during configuration validation. Display padding is a minimum: when a record's number digit count exceeds `id_padding`, the ID uses the wider number (REQ-001.007, ADR-0008).

## Acceptance Criteria

- Creating a supported record automatically assigns it an ID.
- Archiving and restoring a task does not change its ID, and archiving a document does not change its ID; documents have no restore command (REQ-005.007), and milestones are never archived because `papyrus milestone close <id>` changes `open` to `closed` in place (REQ-003.001).
- With default configuration, task, milestone, and release IDs use the documented prefixes and three-digit examples (`TASK-001`, `MS-001`, `REL-001`); the configured prefix and padding control their format.
- A document record's ID shape is determined by its document model and is seed-only; `id_shape` is not a configuration key, and a declaration of `id_shape`, `model`, `title`, or `content` is rejected (REQ-007.002, REQ-007.004).
- A `SingleMarkdown` or `SingleHtmlMockup` record has a plain ID `<PREFIX>-<number>` using the type's configured `prefix` and `id_padding`.
- A `GroupedMarkdown` group has a plain ID `<PREFIX>-<group-sequence>` and its member records have dotted IDs `<PREFIX>-<group-sequence>.<member-sequence>` under the same type prefix.
- A user-defined document type is `SingleMarkdown`, so it has a plain ID; reusing a seed prefix, directory, or field name does not give it a grouped or HTML ID shape.
- `id_padding` governs the generated numeric width as a minimum; when a record's number digit count exceeds `id_padding`, the wider number is used, never truncated (REQ-001.007).
- `id_padding` must be between 1 and 6 inclusive; values outside this range are rejected with clear error messages (REQ-001.007).
- Papyrus uses a single ID space: the same Papyrus ID is written to the front-matter `id` and displayed by CLI and browser output, and it is the only accepted command input form for that record.
- No Backlog.md storage ID (for example `task-18` or `m-0`) is treated as a Papyrus record identity or accepted as command input.
- Records imported from a Backlog.md store receive Papyrus IDs; the import does not create or preserve a parallel Papyrus-visible ID space.
