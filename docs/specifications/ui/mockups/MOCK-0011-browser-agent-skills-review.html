1. Project setup and init

Initialize a new project

Create the project skeleton and write the initial configuration.

papyrus init --dir ./my-project

Inspect effective configuration

Prefixes, padding, statuses, enabled types, and directories are read from papyrus.config.yml with built-in defaults.

papyrus config list

2. Backlog, tasks, milestones, releases

Task IDs and statuses

New tasks use prefix TASK with padding 3: TASK-001. Statuses flow ToDo → Initiated → Refined → Implemented → Validated → Done.

papyrus task create "Title" --status ToDo

Milestones and releases

Milestone IDs use prefix MS (MS-001); release IDs use prefix REL (REL-001). Release lifecycle is separate from task workflow status.

papyrus milestone create "Title"
papyrus release create "Title"

3. Requirements and documentation management

Document types and directories

Enabled types (req, nfr, glossary, rule, ui-spec, ui-mockup, audit, deploy, tech-spec) are stored under docs/ in their configured directories. Disabled types are hidden.

papyrus req create "Title"
papyrus nfreq create "Title"

Business rules, glossary, specifications

Rules, glossary terms, UI specs, technical specs, and mockups follow the same record lifecycle: active → deprecated (restored via restore).

papyrus rule create "Title"
papyrus glossary create "Term"

4. Search

Search across records

Search spans enabled document and decision types; disabled types are excluded.

papyrus search "query"

5. Browser usage

Serve the local browser

Offline, loopback by default. No internet connection required.

papyrus browser --port 6420

6. Release and audit workflows

Releases and audits

Releases move active → released; audit records are created for release audits. Decision types enabled: adr, bdr.

papyrus release status REL-001 released

7. Configuration management

Set and unset keys

Prefixes, padding, statuses, enabled types, and directories are configuration keys (BR-016).

papyrus config set task_prefix TASK
papyrus config unset statuses

8. Decisions

Decision records

Enabled decision types: adr, bdr. Lifecycle: proposed → accepted | rejected; accepted → deprecated | superseded.

papyrus decision create --type adr "Title"
