# REQ-005.014 Manage Test Reports

> **Deprecated.** Superseded by REQ-005.015. This record mixed the test-report activity with the document-model requirement that now covers it; it is retained only for traceability.

## User Story

As a project contributor, I want to create, find, and maintain Test Report documents so that test execution results, pass/fail outcomes, and verification evidence can be documented and traced.

## Description

`test-report` is a `SingleMarkdown` document type (REQ-007.004): one record per plain ID `TR-<n>`, stored under `test-reports/` below `doc_directory` by default, with a Markdown body. Test reports capture the results of test executions, including pass/fail status, test case coverage, and verification evidence.

**Declared fields.** The type's field set is seed data and is not declared in project configuration (ADR-036 decisions 26 and 29):

- `description` — stored under the heading `## Description`.
- `applicability` — stored under the heading `## Applicability`.

Both fields are optional and body-only: either may be omitted or cleared, and each value is stored in the record body under its declared heading, never in YAML front matter. Field sequence position is the order of the fields everywhere — body sections, CLI options and help, and the browser form (ADR-036 decision 20). The record title is required on create under the uniform title contract and is not a field (RE-010 D13, REQ-005.010). No other field belongs to this type; adding or changing a field is a configuration file edit (REQ-007.002).

**Title and options.** `papyrus test-report create <TITLE> --description <TEXT> --applicability <TEXT>` creates a test report; `--title` is accepted on create and edit. The title is single-line and non-empty, is required on create, and can never be cleared by an edit; supplying both the positional `TITLE` and `--title` is rejected and writes nothing (REQ-007.003). `--description` and `--applicability` are the field options, and a `multiline` field option accepts `-` to read the value from standard input. Labels and references remain general metadata supplied through `--label` and `--reference` (REQ-005.010). No create or edit option sets `status` (REQ-005.011).

**Command family.** The verbs are derived from the `SingleMarkdown` model: `create`, `list`, `view`, `edit`, `archive`, `delete`, and `status` (REQ-007.003). The slug and defaults come from the `test-report` configuration entry (REQ-007.002).

**Lifecycle.** Test reports carry front-matter `status` with the value `active`, a declared custom status, or `archived`; only the `status` and `archive` verbs write it (REQ-007.001). Archiving hides a test report from lists, search, and the web UI, moves it to the type's `archived/` subfolder, and preserves its ID (REQ-005.007). Deletion permanently removes the record with confirmation, and `--force` skips the prompt (REQ-005.007). Reference visibility for this type is `visible`, so a list row renders its reference list (ADR-036 decision 29).

## Acceptance Criteria

- `test-report` is a `SingleMarkdown` document type whose model comes from the seed table, with one record per plain ID `TR-<n>` (REQ-007.004).
- The type declares exactly the fields `description` under the heading `## Description` and `applicability` under the heading `## Applicability`, in that sequence order.
- Both fields are optional: a create that supplies only a title succeeds, and an edit may supply or clear either field.
- Each field value is stored in the record body under its declared heading, and neither field declares a front-matter key.
- Field sequence position governs body section order, CLI option and help order, and browser form order.
- `papyrus test-report create <TITLE>` creates a test report with the first positional `TITLE`, and `--title` is accepted on create and edit.
- A create without a title, with an empty title, with a multi-line title, or with both the positional `TITLE` and `--title` is rejected and writes no file; an edit cannot clear the title.
- `--description` and `--applicability` are the field options, and a `multiline` field option accepts `-` to read the value from standard input.
- No create or edit option sets `status`, and labels and references are supplied through `--label` and `--reference`.
- Test reports can be listed, viewed, and edited for title and description.
- The command family is `papyrus test-report create|list|view|edit|archive|delete|status`, derived from the `SingleMarkdown` model, with the slug and defaults defined by the `test-report` configuration entry (REQ-007.002, REQ-007.003).
- A list row for a `test-report` record renders its reference list because the seed reference visibility of the type is `visible`.
- Test reports can be archived; archiving hides them from lists, search, and the web UI, moves them to the type's `archived/` subfolder, and preserves their ID (REQ-005.007).
- Test reports can be permanently deleted with confirmation, and `--force` skips the prompt (REQ-005.007).
- Test reports have no restore command (REQ-005.007).
