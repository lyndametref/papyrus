# REQ-002.001 Manage Tasks

## User Story

As a project contributor, I want to create, update, archive, restore, and delete tasks so that planned work and its progress stay recorded and current.

## Group

REQ-002 Task and Board Management

## Criticality

Must have

## Description

**Create.** `papyrus task create <TITLE>` creates a task. The title is required and is the first positional argument. The task carries an optional description, repeatable acceptance criteria, repeatable dependencies, an optional milestone, repeatable labels, repeatable references, a list of assignees, an optional ordinal, and the task status.

A multiline description accepts `-` to read its value from standard input. References may name any managed record; no record type is excluded. Labels carry free-form classification. `papyrus task create --help` lists the options.

**Identifier and status.** Task identifiers use the configured task prefix and the shared `id_padding` (REQ-001.005); with default configuration the first identifier is `TASK-001`. A new task starts at the configured default task status, `ToDo` with default configuration (REQ-001.002).

**Ordinal.** The ordinal is a non-negative whole number giving the task its execution order. It is optional on create; when omitted it is derived from the current maximum (REQ-005.011). It is the value by which the Backlog board orders milestones and releases (REQ-006.013).

**Edit.** `papyrus task edit <ID>` changes the title, description, status, milestone (including clearing it), assignees, labels, references, or ordinal. Repeatable add-options append acceptance criteria and dependencies to the existing sets rather than replacing them. `--editor` opens the task body in the configured editor; option-only edits update the metadata without opening an editor.

**Archive and restore.** `papyrus task archive <ID>` takes the task off the working set and moves it to the backlog archive folder for tasks, preserving its identifier, its status, its dependencies, and its references. An archived task remains viewable and is not editable: an edit is rejected with a validation outcome and writes nothing. `papyrus task restore <ID>` returns an archived task to the working set with the status it had before archiving and the same identifier.

**Delete.** `papyrus task delete <ID>` permanently removes a task. A task that is not archived is archived first. Deletion asks for confirmation, and `--force` skips the prompt.

## Acceptance Criteria

- `papyrus task create <TITLE>` creates a task and reports its identifier.
- The title is required; the description, acceptance criteria, dependencies, milestone, labels, references, assignees, and ordinal are optional.
- A multiline description accepts `-` to read its value from standard input.
- Repeatable options accept multiple values on both create and edit.
- References may name any managed record, and no record type is excluded.
- A new task receives the configured task prefix and `id_padding`; with default configuration the identifier is `TASK-001`.
- A new task starts at the configured default task status; with default configuration the status is `ToDo`.
- The ordinal is a non-negative whole number, is optional on create, and defaults to the current maximum when omitted.
- `papyrus task edit <ID>` changes the title, description, status, milestone, assignees, labels, references, and ordinal.
- An edit can clear the milestone.
- Repeatable add-options on edit append acceptance criteria and dependencies instead of replacing the existing sets.
- `--editor` opens the task body in the configured editor, and an option-only edit updates the metadata without opening an editor.
- `papyrus task archive <ID>` moves the task into the backlog archive folder for tasks and preserves its identifier, status, dependencies, and references.
- `papyrus task restore <ID>` returns an archived task to the working set with its previous status and the same identifier.
- An archived task remains viewable and is not editable until restored.
- `papyrus task delete <ID>` permanently removes a task, archiving it first when it is not archived.
- Deletion asks for confirmation, and `--force` skips the prompt.
