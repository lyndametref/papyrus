# REQ-005.006 Manage Audit Records

> **Deprecated.** Superseded by REQ-005.015. This record mixed the audit record activity with the document-model requirement that now covers it; it is retained only for traceability.

## User Story

As a project contributor, I want to record and maintain audit information so that the project can retain searchable audit records.

## Group

REQ-005 Project Documentation Management

## Criticality

Must have

## Description

`audit` is a `SingleMarkdown` document type (REQ-007.004): one record per plain ID `AUD-<n>`, with a Markdown body.

**Declared fields.** The type's field sequence is seed data and is not declared in project configuration (ADR-036 decisions 14, 26, and 29):

1. `audit_type` — stored under the heading `## Audit Type` and in the front-matter key `type`, option `audit-type`.
2. `content` — stored under the heading `## Content`, required.

`audit_type` is the case where the storage key differs from the field key: the field is named `audit_type`, its CLI option is `--audit-type`, and its front-matter key is `type` (ADR-036 decision 14). Because the field declares both a heading and a front-matter key, a write sets both locations from the same submitted value and a read displays the body section without merging the two; a divergence already on disk is left as stored (ADR-036 decision 21, ADR-039 decision 16). `content` is body-only and declares no front-matter key. Field sequence position is the order of the fields everywhere — body sections, CLI options and help, and the browser form (ADR-036 decision 20). The record title is not a field (REQ-005.010), and no other field belongs to this type.

**Create and title.** `papyrus audit create <TITLE> --content <TEXT>` creates an audit record. The positional `TITLE` is added to the audit command under the uniform title contract: `--title` keeps its current name and meaning and remains accepted on create and edit, the title is single-line and non-empty, is required on create, and can never be cleared by an edit, and supplying both the positional `TITLE` and `--title` on one invocation is rejected and writes nothing (RE-010 D13, REQ-007.003). `content` is required, so a create that omits it, or an edit that clears it, is rejected with one validation outcome and writes no file (ADR-036 decision 18).

**Audit types.** Built-in audit types are `security` (the default when `--audit-type` is omitted), `licence`, and `architecture`; additional audit types are configurable. The audit type is record data stored in the `audit_type` field, not a document type, a status, or a configuration key of its own.

**Lifecycle.** Audit records carry front-matter `status` with the value `active`, a declared custom status, or `archived`; only the `status` and `archive` verbs write it (REQ-007.001, REQ-005.011). Archiving hides a record from lists, search, and the web UI, moves it to the type's `archived/` subfolder, and preserves its ID (REQ-005.007). Deleting a record permanently removes it under the document deletion rules (REQ-005.007). Reference visibility for this type is `visible`, so a list row renders its reference list (ADR-036 decision 29).

## Acceptance Criteria

- `audit` is a `SingleMarkdown` document type whose model comes from the seed table, with one record per plain ID `AUD-<n>` (REQ-007.004).
- The type declares exactly the fields `audit_type` and `content`, in that sequence order.
- `audit_type` is stored under the heading `## Audit Type` and in the front-matter key `type`, and its CLI option is `--audit-type`.
- A write of `audit_type` sets both the body section and the front-matter `type` key from the same value, and a read displays the body section without merging the two locations.
- `content` is stored under the heading `## Content`, is required, and declares no front-matter key.
- A create that omits `content`, or an edit that clears it, is rejected with one validation outcome and writes no file.
- Field sequence position governs body section order, CLI option and help order, and browser form order.
- `papyrus audit create <TITLE> --content <TEXT>` creates an audit record with the positional `TITLE`; `--title` remains accepted on create and edit with its current name and meaning.
- A create without a title, with an empty title, with a multi-line title, or with both the positional `TITLE` and `--title` is rejected and writes no file; an edit cannot clear the title.
- The audit type defaults to `security` when `--audit-type` is omitted; `licence` and `architecture` are also built in, and additional audit types may be configured.
- Audit records can be listed, viewed, and edited for title, content, and audit type.
- No create or edit option sets `status`, and labels and references are supplied through `--label` and `--reference`.
- A list row for an `audit` record renders its reference list because the seed reference visibility of the type is `visible`.
- Archiving an audit record hides it from lists, search, and the web UI, moves it to the type's `archived/` subfolder, and preserves its ID (REQ-005.007).
- Deleting an audit record permanently removes it under the document deletion rules (REQ-005.007).
