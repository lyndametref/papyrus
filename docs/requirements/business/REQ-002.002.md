# REQ-002.002 View and List Backlog Items

## User Story

As a project contributor, I want to inspect a backlog record and find the ones that matter so that I can focus on relevant work.

## Group

REQ-002 Backlog Management

## Criticality

Must have

## Description

This requirement covers viewing and listing the three backlog record types: tasks (REQ-002.001), milestones (REQ-002.005), and releases (REQ-002.006).

**View.** `papyrus task view <ID>` shows a task, and `papyrus task <ID>` shows the same task; the identifier shorthand exists for tasks only. A task view shows the identifier, title, status, description, acceptance criteria, milestone, assignees, labels, references, dependencies, ordinal, and the created and updated dates. `papyrus milestone view <ID>` shows a milestone's identifier, title, status, description, assigned release, acceptance criteria, labels, and references. `papyrus release view <ID>` shows a release's identifier, title, status, description, labels, and references. `papyrus task view <ID> --ac` prints only the acceptance criteria of a task, and `papyrus milestone view <ID> --ac` prints only those of a milestone; plain text lists one criterion per line and `--json` renders the list as an array.

**Task list.** `papyrus task list` prints tasks as plain text by default and honours the global `--json` option (REQ-001.004). It filters by status, milestone, release, label, assignee, and free text, where a release filter includes the tasks whose milestone belongs to that release. `--limit` caps the number of rows, `--sort <field>` orders them by the named field, and `--watch` keeps the list open and refreshes it when records change. Filters combine with one another.

**Milestone and release lists.** `papyrus milestone list` and `papyrus release list` print their records as plain text or JSON. They accept no filter beyond the global options.

**Readiness.** `--ready` on the task list restricts it to unfinished tasks whose every dependency has reached the project's final task status. The final task status is the last entry of the configured task status list (REQ-001.002). A task is unfinished when its status is not that final status. Readiness is derived at read time from the stored dependencies and is never stored as a field. It fails closed: a dependency that is missing, unknown, ambiguous, self-referential, part of a cycle, or not in the final status blocks its dependent task. An archived dependency counts as resolved only when it is in the final status.

## Acceptance Criteria

- `papyrus task view <ID>` and `papyrus task <ID>` display the same task, and the identifier shorthand exists for tasks only.
- A task view shows the identifier, title, status, description, acceptance criteria, milestone, assignees, labels, references, dependencies, ordinal, and the created and updated dates.
- `papyrus milestone view <ID>` shows the identifier, title, status, description, assigned release, acceptance criteria, labels, and references.
- `papyrus release view <ID>` shows the identifier, title, status, description, labels, and references.
- `papyrus task view <ID> --ac` prints only the task's acceptance criteria, and `papyrus milestone view <ID> --ac` prints only the milestone's.
- `--ac` output lists one criterion per line in plain text and as an array under `--json`.
- Each documented task-list filter restricts the results to matching tasks, and a release filter includes the tasks on milestones assigned to that release.
- `--limit` caps the number of rows and `--sort <field>` orders them by the requested field.
- `--watch` keeps the task list open and refreshes it when records change.
- The task list prints plain text by default and honours the global `--json` option.
- Filters combine with one another.
- `papyrus milestone list` and `papyrus release list` print their records as plain text or JSON and accept no filter beyond the global options.
- `--ready` restricts the task list to unfinished tasks whose every dependency is in the final configured task status.
- A task is unfinished when its status differs from the final configured task status, which is the last entry of the configured status list.
- A dependency that is missing, unknown, ambiguous, self-referential, cyclic, or not in the final status blocks its dependent task.
- An archived dependency counts as resolved only when it is in the final status.
- Readiness is derived at read time and is not stored in task metadata.
- `--ready` combines with the other documented task-list filters.
