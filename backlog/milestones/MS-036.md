## Description
Internal checkpoint of one deliverable: latency and caching, no functional change.

Goal: meet NFR-07.001 and NFR-07.002 and stop re-reading configuration per record and per request, per ADR-B and ADR-C. Keep the mtime config/registry cache (owner decision 11).

Reference hardware decision (recorded 2026-11-22T20:22:22Z):
NFR-007.001 and NFR-007.002 name 4 vCPU and 8 GiB RAM. The only available host has 6 physical and 12 logical cores and 15.3 GiB. MS-036 measures on that available host with the full NFR-007 protocol and records the hardware deviation beside every result. The figures are reported as measured values with the deviation attached; they do not satisfy NFR-007.001 or NFR-007.002, and this milestone does not mark either NFR satisfied. MS-037 presents the figures with the deviation as a caveat for the owner, who decides between re-measurement on reference hardware and accepting the deviation.

Packaging waiver (user-approved, recorded 2026-11-22T20:22:22Z):
- Scope: MS-036 only.
- Reason: MS-037 AC-6 and AC-7 require exactly one retained release artifact; an RC package from an intermediate checkpoint would create a second retained artifact at the single-release boundary.
- Effect: after every quality and code check passes, milestone verification compiles and discards a verification build; no RC version is determined and no package is retained.

ADR-043 exception (architect action):
ADR-043 decision 21 states that every verified milestone from MS-035 onward publishes an RC package. That is wrong for MS-035 and MS-036: both are internal checkpoints whose verification builds are discarded, and the packaging gate effectively starts at MS-037. The architect must amend ADR-043 decision 21 to except MS-035 and MS-036. This milestone records the exception; planning does not edit ADR-043.

Acceptance criteria:
AC-1 Inventory p95 < 250 ms at 1,000 records, measured with the full NFR-007.001 protocol by the MS-032 harness on the available host (6 physical / 12 logical cores, 15.3 GiB), with the hardware deviation recorded beside the result; the result is reported as a measured figure with the deviation and does not mark NFR-007.001 satisfied.
AC-2 View and edit p95 < 100 ms at 1,000 records, measured with the full NFR-007.002 protocol on the same available host, with the hardware deviation recorded beside every route result; the results are reported as measured figures with the deviation and do not mark NFR-007.002 satisfied.
AC-3 One scheduler-independent inventory build uses a single registry-wide scan; no per-record config read, YAML parse, validation, or registry construction remains on the read path.
AC-4 A request-scoped snapshot (id to Record) serves all title and reference resolutions; no write content or version token is derived from the snapshot.
AC-5 The mtime-invalidated snapshot of config, registry, and routes swaps atomically and fails closed on reload error while the last known good snapshot keeps serving.
AC-6 Vendor assets get versioned immutable caching; app.css and app.js get no-cache with ETag and 304; HTML and JSON stay no-store; assets only; no compression.
AC-7 The 3.57 MB Mermaid and 275 KB KaTeX payloads are no longer sent no-store; Mermaid renders lazily.
AC-8 Connection behavior stays keep-alive; no change unless the recorded benchmark shows a need.
AC-9 Internal checkpoint: after every quality and code check passes, milestone verification compiles and discards a verification build; no RC version is determined and no package is retained, in line with MS-032 to MS-035 verification (AUD-138, AUD-140, AUD-147) and MS-037 AC-6 and AC-7. The packaging entry point scripts/build-package.sh (ADR-043) may be exercised during verification, but any artifact it produces is discarded.
