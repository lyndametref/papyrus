# REQ-001.006 Interactive Init Walkthrough at `papyrus init <project_name>`

## User Story

As a project maintainer, I want the initialization to ask which artifacts I want so that the generated configuration matches the project.

## Group

REQ-001 Project Setup and CLI Access

## Criticality

Should have

## Description

At `papyrus init <NAME>` (also with `--dir` or `PAPYRUS_DIR`), an interactive walkthrough runs before `papyrus.config.yml` is written. It presents the offered artifacts as one cursor-driven list: exactly one selectable row is highlighted, starting on the first selectable row; the up and down arrow keys (or `k` and `j`) move the highlight; the space key toggles the highlighted row; Enter confirms the list and continues. The list redraws after every keypress so the highlight and each row's `[x]`/`[ ]` state stay visible, and navigating past the first or last row keeps the highlight on that row. Typed token input, such as space-separated names on one line, is not an acceptable presentation, and end of input confirms the current state instead of waiting.

The offered artifacts are the core artifacts task, milestone, and release, the decision types, and the document types of the Seed (REQ-005.016). The core artifacts are always written, are shown as such, and are never highlighted or toggled, because they are not document types; their prefixes are still prompted. For every selected decision type and document type the walkthrough prompts the identifier prefix and the storage folder, and the shared roots (`backlog_directory`, `decision_directory`, `doc_directory`) are prompted once. Prompts show their default in brackets, and invalid input re-prompts with a hint naming the default.

**What is written.** Each selected document type is written into `papyrus.config.yml` in full, and an unselected type is not written at all. A run without an interactive terminal skips the walkthrough and writes every Seed entry in full with the default prefixes and folders, so an unattended run never waits on a prompt and requires no new flag or environment variable.

## Acceptance Criteria

- The walkthrough presents the offered artifacts as one list with exactly one highlighted row, starting on the first selectable row.
- Arrow keys, or `k` and `j`, move the highlight; space toggles the highlighted row; Enter confirms the list; end of input confirms the current state.
- The list redraws after each keypress, showing the highlight and every row's `[x]`/`[ ]` state, and the highlight never moves past the first or last row.
- Typed token input is not accepted as the selection mechanism.
- The offered artifacts are task, milestone, release, the decision types, and the document types of the Seed.
- Task, milestone, and release are always written, are shown as always included, and are never highlighted or toggled; their prefixes are still prompted.
- Only selected decision types and document types are written, each in full; unselected types are not written.
- For each selected decision type and document type, its prefix and storage folder are prompted, and each shared root is prompted once.
- Prompts show their default in brackets and accept it with empty input.
- An invalid prefix or folder is rejected and re-prompted with a hint naming the default.
- The configuration written matches the state shown when Enter was pressed.
- A run without an interactive terminal writes every Seed entry in full with the default prefixes and folders, without prompting.
- The walkthrough requires no new command-line flag or environment variable.
- `--force` and `--no-git` behave as documented in REQ-001.001.
- The generated configuration validates successfully, including the `id_padding` range (REQ-001.005).
