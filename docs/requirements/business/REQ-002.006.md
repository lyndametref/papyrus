# REQ-002.006 Manage Releases

## User Story

As a project maintainer, I want to create, close, archive, and delete releases so that milestones can be grouped for planned delivery and finished delivery records leave the working set.

## Group

REQ-002 Backlog Management

## Criticality

Must have

## Description

`papyrus release create <TITLE>` creates a release with a title and an optional description. Its identifier uses the configured release prefix and the shared `id_padding` (REQ-001.005); with default configuration the first identifier is `REL-001`. A release may contain multiple milestones, while each milestone is assigned to at most one release (REQ-002.005).

**Lifecycle.** The release lifecycle is fixed by the backlog category (REQ-007.001): `planned`, then `released`, then `archived`. A new release starts `planned`, and the state is stored in the front-matter `status` field (REQ-005.010). The lifecycle is not configurable, and there is no restore command.

`papyrus release close <ID>` changes `planned` to `released`; `released` means the delivery happened. Closing a release that is not planned is rejected with a validation outcome and writes nothing. `papyrus release archive <ID>` closes a release that is still planned and then sets it `archived`, moving the file to `backlog/archive/releases/`. An archived release is hidden from active lists and from the Backlog board, and keeps its identifier.

**Edit.** `papyrus release edit <ID>` changes the title or the description. No option sets the lifecycle state apart from `close` and `archive`.

**Delete.** `papyrus release delete <ID>` permanently removes the release. Deletion asks for confirmation, and `--force` skips the prompt.

**Milestones are not cascaded.** Archiving or deleting a release changes no milestone: each milestone keeps its file, its state, and its release assignment. A milestone that still names a release that no longer exists is reported as a dangling reference by `papyrus check` (REQ-001.008).

Listing and viewing releases belong to REQ-002.002.
