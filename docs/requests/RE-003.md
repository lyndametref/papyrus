# RE-003 Browser edits return 403 due to origin validation

## Description
Context: When performing edits from the browser (edit artifact, clean up all done tasks, etc.), the server returns HTTP 403. The likely cause is `validate_origin` in `src/browser/mod.rs`, which rejects POST requests unless the `Origin` header exactly matches `http://<Host header>` (with only `:80` normalization). Real browsers can send origins that differ from the raw Host header (e.g. localhost vs 127.0.0.1, IPv6 brackets, https, or `Origin: null`), causing legitimate same-site edits to fail.

Requested outcome: Make browser POST origin validation accept any origin whose host is in the allowed host set, normalize ports/IPv6/https, and keep `Origin: null` forbidden. Add regression tests for cross-host and IPv6 origins.
