# REQ-005.016 Provide the Seed

## User Story

As a project maintainer, I want `init` to offer the built-in document types so that I can choose which ones my project configures.

## Group

REQ-005 Project Documentation Management

## Criticality

Must have

## Description

**What the Seed is.** The Seed is defined by one configuration file kept in the source tree and compiled into the shared core library at build time. It is the built-in list of default record types that the `init` walkthrough offers for selection (GLO-013, REQ-001.006). It has two families: the `document_types` map of that file is the document-type Seed, defined here, and its `decision_types` map is the decision-type Seed, defined in REQ-004.001. This requirement owns the document-type Seed and does not restate the decision-type entries. No seed file is read at runtime, and changing the Seed requires a rebuild.

**Lifecycle.** The walkthrough presents the Seed during `init`. A selected entry is written into `papyrus.config.yml` fully expanded — document model, field sequence, identifier prefix, directory, custom workflow status set, list slots, and field defaults. An unselected entry is not written at all. A run without an interactive terminal writes every entry.

**After `init` the Seed is irrelevant.** No command, view, search, validation, or default resolution reads it. The project configuration is the only source of document types (REQ-007.002), and a document type exists if and only if the configuration declares it. There is no `enabled` key: presence in the configuration is the only switch, and removing an entry removes the type.

**Content.** The document-type Seed contains exactly these entries; the criticality column is a requirement attribute of the built-in type, not a configuration key.

| Slug | Document model | Criticality | Prefix | Field sequence | Workflow statuses |
|---|---|---|---|---|---|
| `req` | `grouped-record` | Must have | `REQ` | group and member: `story`, `description` | none |
| `nfr` | `grouped-record` | Must have | `NFR` | group and member: `story`, `description` | none |
| `glossary` | `simple-record` | Must have | `GLO` | `definition` (required) | none |
| `rule` | `simple-record` | Must have | `BR` | `description` (required, create and edit), `rationale` (required, create only), `applicability` (required, create only), `requirements` (list, option `requirement`) | none |
| `ui-spec` | `simple-record` | Must have | `UI` | `view`, `description` | none |
| `tech-spec` | `simple-record` | Must have | `TECH` | `description` | none |
| `audit` | `simple-record` | Must have | `AUD` | `audit_type` (option `audit-type`, default `security`), `content` (required) | none |
| `use-case` | `simple-record` | Should have | `UC` | `description`, `applicability` | none |
| `test-case` | `simple-record` | Should have | `TC` | `description`, `applicability` | none |
| `test-report` | `simple-record` | Should have | `TR` | `description`, `applicability` | none |
| `ui-mockup` | `formatted-record` | Must have | `MOCK` | none (`fields: []`) | fixed `draft`, `approved`; archived is a file position |

All fields are body fields under their own headings except `audit_type`, which is metadata-only and stored under its key, and all fields are optional unless marked required. Heading, kind, option, and verb values are those of this table. No entry declares `active` or `archived`: `active` describes any non-archived state and `archived` is the storage state (REQ-007.001).

**One definition.** This requirement is the only definition of the built-in document types. No other requirement or table defines a built-in type, its fields, or its defaults; the compiled Seed configuration file implements this requirement and must match it.

## Acceptance Criteria

- The Seed has two families, the document-type Seed and the decision-type Seed, and this requirement owns the document-type one.
- The Seed is one configuration file in the source tree, compiled into the shared core library at build time; no seed file is read at runtime.
- The document-type Seed is the list of document types offered by the `init` walkthrough, and `init` is the only command that reads it.
- A selected entry is written into `papyrus.config.yml` fully expanded: document model, field sequence, identifier prefix, directory, custom workflow status set, list slots, and field defaults.
- An unselected entry is not written.
- A run without an interactive terminal writes every Seed entry.
- The Seed is not read by any command, view, search, validation, or default resolution after `init`.
- The project configuration is the only source of document types, and a document type exists if and only if the configuration declares it.
- There is no `enabled` key; presence in the configuration is the only switch, and removing an entry removes the type.
- The document-type Seed contains exactly the eleven entries of the table above, with the document model, prefix, field sequence, and statuses stated there.
- The decision-type Seed is not repeated here; it is defined in REQ-004.001.
- The criticality column is a requirement attribute of the built-in type and is not a configuration key.
- A field is optional unless the table marks it required, and each field's declared verbs, kind, and option are as stated.
- No other requirement or table defines a built-in document type; the compiled Seed configuration file implements this requirement and must match it.
