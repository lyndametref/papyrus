# REQ-008.001 Provide the Papyrus Manual

## User Story

As a Papyrus user, I want a manual page on my machine so that I can read the complete reference without network access or the project source.

## Group

REQ-008 User Documentation

## Criticality

Must have

## Description

Papyrus ships a manual page that the package installs to the standard manual path, so that `man papyrus` displays the reference. A second page, `papyrus-config(5)`, carries the configuration reference and is reached with `man papyrus-config`.

**Content of `papyrus(1)`.** The name and synopsis, the description, the global options, the environment variables, the files Papyrus reads and writes, the exit statuses, and every built-in command with its arguments and options. The manual states once, against the `<slug>` placeholder, the command family that applies to every configured document type and to every configured decision type: the model-derived verbs, the field options, and the title contract for documents, and the verbs of a decision type. It also explains how a slug is configured — which configuration map declares it (`document_types` or `decision_types`), which entry keys apply, and that the slug is both the configuration key and the command name. A specific type's options are not enumerated in the manual; they appear in that type's own command help (REQ-008.002).

**Content of `papyrus-config(5)`.** The configuration file location, the precedence between command-line options, environment variables, and configuration values, every configuration key with its default and accepted values, and the model-level defaults that apply to a document type.

**Availability.** The manual is installed with the package at the standard manual path, is readable with the system manual reader, and requires no network access. The packaged source is the single source of the manual text: the installed pages and the `papyrus help` output are generated from it (REQ-008.003).

## Acceptance Criteria

- `man papyrus` displays the Papyrus manual after installation.
- `man papyrus-config` displays the configuration manual after installation.
- `papyrus(1)` documents the name and synopsis, description, global options, environment variables, files, exit statuses, and every built-in command with its arguments and options.
- `papyrus(1)` states the document-type and decision-type command families once, against the `<slug>` placeholder, rather than enumerating each configured type.
- The `<slug>` section explains how a slug is configured: its configuration map, its entry keys, and the fact that the slug is both the configuration key and the command name.
- `papyrus-config(5)` documents the configuration file location, the precedence rules, every configuration key with its default and accepted values, and the model-level defaults.
- The manual is installed at the standard manual path by the package and needs no network access.
- The manual content is generated from a single packaged source, and the `papyrus help` output is produced from the same source.
- A command added to the CLI is documented in the manual before the release that ships it.
