# REQ-05.010 Record Metadata in YAML Front Matter

## User Story
As a project contributor, I want every managed file to begin with structured record metadata so that records can be identified, related, filtered, and displayed consistently without reading the document body.

## Group
REQ-05 Project Documentation Management

## Criticality
Must have

## Description
Every Markdown file managed by Papyrus begins with a YAML front-matter block. The block carries the general fields `id`, `title`, `created_date`, `updated_date`, `labels`, and `references` for every managed record type, followed by the type-specific fields. Task front matter carries exactly the Backlog.md key set `id`, `title`, `status`, `assignee`, `created_date`, `updated_date`, `labels`, `milestone`, `dependencies`, `references`, `documentation`, `type`, and `ordinal`; `assignee` is a YAML list. Milestone front matter carries the general fields plus `release`. Backlog.md milestone files currently carry only `id` and `title`, so the added general fields and `release` are additive: Backlog.md must still read, list, and update these files, with the added keys accepted and preserved (NFR-04.003). Release records carry the general fields only; no release-state field is defined here because REQ-03.002 does not define a stored release state. A decision's front matter may carry `superseded_by`, and front matter is additive for decisions: the existing `## Date` and `## References` sections remain part of the body, `created_date` is the front-matter timestamp and does not replace or duplicate the ADR `## Date` line, and neither section becomes an editable metadata source. Decision `status` stays in the document core and decision `type` (`adr`/`bdr`) stays derived from the record ID prefix; neither moves to front matter. Audit records carry `type`.

Scope is Markdown records. UI mockups are excluded: their status, associated task, and references remain stored in the mockup's HTML content (REQ-05.008), which is the single source for mockup metadata, and mockup HTML files carry no front matter. Backlog.md `docs` and `drafts` records are out of scope because they are Backlog.md-owned. For tasks and milestones the front-matter `id` and the reference values in `milestone:` and `dependencies:` are the Backlog.md storage form, not the command input form: commands accept only the Papyrus display ID (REQ-01.005).

Front matter is authoritative for the fields it carries and replaces the equivalent information in the document core for records Papyrus writes, so no retired metadata section stores a field that front matter carries; frozen decision bodies are the exception described above. Key order and YAML quoting follow the Backlog.md-compatible serialization for tasks and milestones, and general keys precede type-specific keys elsewhere. Tasks and milestones have no `# <ID> <title>` heading because the Backlog.md body has none. Every other Markdown record type keeps a `# <ID> <title>` body title line that the writer generates from the front-matter `id` and `title`, so the two cannot diverge; frozen ADR bodies keep their existing heading and gain front matter only. Timestamps are quoted ISO-8601 UTC strings, for example `'2026-10-31T22:26:00Z'`. Adding front matter to an existing record does not change its body, except for the legacy Papyrus-shape task and milestone conversion defined in REQ-05.011.

## Acceptance Criteria
- Every managed Markdown record file created by Papyrus begins with a YAML front-matter block at byte 0, delimited by `---` lines.
- Every managed Markdown record type carries `id`, `title`, `created_date`, `updated_date`, `labels`, and `references` in its front matter.
- Task front matter carries `id`, `title`, `status`, `assignee`, `created_date`, `updated_date`, `labels`, `milestone`, `dependencies`, `references`, `documentation`, `type`, and `ordinal`; `assignee` is a YAML list.
- Milestone front matter carries the general fields plus `release`; Backlog.md reads, lists, and updates such a file and preserves the added keys (NFR-04.003).
- Release front matter carries the general fields only; no release-state field is written.
- A decision's front matter may carry `superseded_by`; adding front matter to a decision leaves `## Date` and `## References` intact and does not move decision `status` or decision `type` into front matter.
- An audit record's front matter carries `type`.
- Tasks and milestones have no `# <ID> <title>` heading; every other Markdown record type keeps a body title line generated by the writer from the front-matter `id` and `title`.
- A frozen ADR body keeps its existing heading and sections; the added front-matter block is the only change made to an existing decision file.
- UI mockup HTML files carry no YAML front matter; mockup metadata stays in the HTML content (REQ-05.008).
- Backlog.md `docs` and `drafts` files are not managed by Papyrus front matter.
- `created_date` and `updated_date` are quoted ISO-8601 UTC strings of the form `'YYYY-MM-DDTHH:MM:SSZ'`.
- No front-matter field is also stored in a retired metadata section of the document core.
- Adding front matter to an existing record leaves the record body unchanged, except for the legacy Papyrus-shape task and milestone conversion defined in REQ-05.011.
