# REQ-006.017 Render Math Formulas and Diagrams in the Browser

## User Story

As a project contributor, I want the browser to render math formulas and diagrams embedded in record content so that technical documentation is legible without leaving Papyrus.

## Group

REQ-006 Search and Local Web Interface

## Criticality

Should have

## Description

The local web interface renders math formulas and Mermaid-style diagrams embedded in the curated prose fields that record views display, so that authors can include mathematical notation and diagrams in Markdown prose and readers see rendered output rather than raw source. Rendering applies to those curated prose fields only. This requirement introduces no separate record-body view, and it does not require rendering of any field or page outside the curated prose a record view already shows. Rendering happens in the browser only: CLI output and every other surface display the source text unchanged.

Math input is recognized in three forms: display math between `$$` delimiters, inline math between single `$` delimiters, and fenced code blocks whose info string is `math`, `tex`, or `latex`. A literal dollar sign is written as `\$` and is not treated as a delimiter. Diagrams are recognized only as fenced code blocks whose info string is `mermaid`. PlantUML is not supported: a fenced `plantuml` block is shown as source text together with a note that the block is not rendered. Rendering is limited to these input forms; any other fence or delimiter is left as ordinary Markdown. The choice of rendering library or framework is an implementation decision; this requirement fixes the supported input forms and the constraints (offline operation, single-binary distribution, and licensing) rather than a named library.

Rendering works fully offline: all rendering assets are bundled with the application and no network request, external service, or server-side rendering process is required. Rendered output conforms to the browser compatibility targets (NFR-005.001) and to the content-width rules of REQ-006.015, under which diagram or visualization content may use the full available window width while surrounding text remains capped. Rendering failures degrade gracefully: unrenderable or malformed input — a delimiter that is not closed, a formula that cannot be parsed, or a diagram whose source is invalid — is shown as its source text with a note instead of breaking the page. Any rendering dependency must be open source and must permit linking in a GPLv3-or-later application (NFR-006.002), and rendered content must not result in arbitrary script execution (NFR-002.002).

## Acceptance Criteria

- Browser record views render display math delimited by `$$…$$` in the curated prose fields they display.
- Browser record views render inline math delimited by `$…$` in the curated prose fields they display.
- A `\$` sequence renders as a literal dollar sign and is not treated as a math delimiter.
- Fenced code blocks with the info string `math`, `tex`, or `latex` render as math formulas.
- Fenced code blocks with the info string `mermaid` render as diagrams.
- A fenced `plantuml` block is shown as source text with a note that it is not rendered; PlantUML diagrams are not rendered.
- Any other fence info string or delimiter is left as ordinary Markdown source.
- Malformed or unrenderable math input falls back to its source text with a note instead of breaking the page.
- Malformed or unrenderable diagram input falls back to its source text with a note instead of breaking the page.
- Rendering is limited to the curated prose fields of record views; no separate record-body view is introduced.
- CLI output and other surfaces show the source text unchanged; rendering is browser-only.
- Rendering requires no network access and works fully offline.
- All rendering assets are bundled with the application; no external service, CDN, or server-side rendering process is used.
- Rendered diagram or visualization content may use the full available window width while adjacent text content stays capped at 1040px (REQ-006.015).
- Rendering works in the supported browsers (NFR-005.001).
- Any rendering dependency is open source and permits GPLv3-or-later linking (NFR-006.002).
- Rendered content does not result in arbitrary script execution (NFR-002.002).
