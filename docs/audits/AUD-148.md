# Code audit MS-036 performance

- Type: code
- Status: issued
- References: MS-036, TASK-273 to TASK-279, TASK-313
- Verdict: corrections required (0 blocker, 2 high, 4 medium, 6 low)

## Scope

MS-036 change set after the MS-035 close: request snapshot, mtime serving snapshot, single-scan inventory, versioned assets with ETag, lazy Mermaid, NFR measurement, read-path optimisation. Files: browser mod, records, render, http, assets, math and sha256; record frontmatter, migrate, store and view; packaging scripts; benchmark harness.

## Checks run

- fmt clean; clippy --all-targets -- -D warnings clean.
- cargo test: 1388 passed, 0 failed, 27 ignored.
- Manual HTTP probes for 304 status line, archive filtering, title parity and front-matter ID resolution.
- Benchmark not re-executed; committed raw JSON and results cross-checked.

## Findings

### High

F1 an externally archived record still in its active directory is counted by inventory and shown in grouped member rows; the full index excludes it. Correction: treat a relocated record as absent (compare canonical path with the listed target, or return the original target) and add archive tests for counts and grouped rows.
F2 the build-path asset-version guard runs only with the opt-in check flag; a normal package assembly does not reject vendor, manifest or copyright mismatches. Correction: call the guard at the start of the normal assembly path and test each mismatch class through a normal build.

### Medium

F3 the front-matter-only grouped index uses a different title precedence than the full loader (front-matter title first versus heading first), so a member can show different titles on the group page and the list.
F4 every 304 response carries the reason phrase Internal Server Error; add the Not Modified arm and assert the status line.
F5 a record whose front-matter id differs from its file stem is no longer addressable by that id; resolve it or record the narrowing with a regression test.
F6 benchmark provenance does not identify the measured production tree for the post-optimisation run, and the second-load JSON has no commit provenance; record a worktree-dirty flag and diff hash, regenerate after the source commit, and correct the results sentence.
F7 the front-matter-only paths duplicate acceptance and projection rules and have already diverged; extract one shared projection and one acceptance predicate (structural fix for F1 and F3).

### Low

F8 dead code after the inventory move (scan_indexes, is_built).
F9 brittle substring-count source audit in the snapshot tests.
F10 NFR-007.003 vendor second load is simulated, not measured; state the basis in the verdict.
F11 inventory passes by 2 ms on a host faster than the reference; record the thin headroom.
F12 MS-036 AC-8 mentions keep-alive but the server sends Connection close and always has; correct the verification wording.

Severity counts: blocker 0, high 2, medium 4, low 6.

## Verdict

corrections required - the performance evidence is consistent and honestly recorded, but F1 is a demonstrated correctness regression in the read path and F2 leaves the asset-version guard off the build path.
