# REQ-006.020 Order Milestones and Releases by Lowest Task Ordinal in the Browser Backlog

> **Deprecated.** Superseded by REQ-006.013, which owns Backlog ordering.

## User Story

As a project contributor, I want Backlog milestones and releases ordered by the earliest task they contain so that the earliest sequenced work is presented first.

## Group

REQ-006 Search and Local Web Interface

## Description

In the browser Backlog view, milestones are ordered by the lowest ordinal among the non-archived tasks assigned to them, ascending, so the milestone containing the lowest-ordinal task appears first. The rule applies both to milestones inside a release and to milestones in the no-release group. Milestones with no non-archived task are ordered after all milestones that have one, by milestone ID ascending. Milestones with equal lowest ordinals are ordered by milestone ID ascending. Releases are ordered by the lowest ordinal among the non-archived tasks in their milestones, ascending; a release with no such task is ordered after all releases that have one, by release ID ascending; releases with equal lowest ordinals are ordered by release ID ascending. The existing release and no-release grouping and the tasks-without-a-milestone section are unchanged. The order is recomputed from current record data on each render.

## Acceptance Criteria

- In the Backlog view, milestones inside each release are ordered by the lowest ordinal of their non-archived tasks, ascending.
- Milestones in the no-release group follow the same ordering rule.
- A milestone with no non-archived task appears after every milestone with tasks in its group, ordered by milestone ID ascending.
- Milestones with equal lowest ordinals are ordered by milestone ID ascending.
- Releases are ordered by the lowest ordinal of the non-archived tasks in their milestones, ascending.
- A release with no non-archived task appears after every release that has one, ordered by release ID ascending.
- Releases with equal lowest ordinals are ordered by release ID ascending.
- Changing a task ordinal and reloading the view changes the position of its milestone and release accordingly.
- Release grouping and the placement of the tasks-without-a-milestone section are unchanged.
