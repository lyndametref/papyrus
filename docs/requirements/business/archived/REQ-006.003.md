# REQ-006.003 Describe Managed Artifacts and Their Lifecycles in the Browser

## User Story

As a project contributor, I want a browser page that describes every artifact and document type managed in the project and its lifecycle so that I can understand what each record type is and how it moves through its states.

## Group

REQ-006 Search and Local Web Interface

## Criticality

Should have

## Description

The local web interface provides a page that describes the artifact and document types managed in the current project, with one section per type, and explains the lifecycle of each type. The page covers the three artifact categories (REQ-007.001):

- **backlog** — tasks, milestones, and releases.
- **decision** — decision records.
- **document** — every document type declared in `document_types`, enabled or not, including the default entries and any type added by configuration (REQ-007.002).

The document sections are therefore derived from the effective configuration and are not a fixed list. The task section's states and transitions are derived from the configured statuses (REQ-001.002); the milestone section shows the fixed `open -> closed` lifecycle; the release section shows the fixed `planned -> released` lifecycle; the decision section shows the five Nygard statuses (REQ-004.001); every document section shows the main `active -> archived` storage lifecycle (REQ-005.007) together with the custom statuses declared for that type (REQ-007.002), and the UI mockup section shows `pending -> approved -> archived` (REQ-005.008). Backlog.md `docs`, `drafts`, and project configuration files are not covered. The page route, navigation entry, and format are design decisions.

Each section provides a good description of its artifact on top of the lifecycle and the existing status, and represents the configuration associated to that artifact. Description text is curated content shipped with the browser for the default types, works offline (NFR-001.003), and is not derived from requirement files, record content, or configuration; a document type added by configuration is described by the shared document lifecycle and its configured prefix and folder, since no curated text is shipped for it. The configuration shown per section is read-only and consists of the artifact's effective `enabled` state, its ID prefix, and its storage folder; the task section additionally presents the configured task statuses, and a document section presents the statuses declared for that document type. Configuration values on this page are display-only: changes are made only through the browser configuration view (REQ-006.008).

## Acceptance Criteria

- The local web interface serves a page that describes every managed artifact and document type in a separate section, grouped by the three artifact categories.
- The page covers tasks, milestones, releases, decision records, and every document type declared in `document_types`, including types added by configuration.
- The document sections are derived from the effective configuration and are not a fixed list.
- The task section's states and transitions reflect the configured task statuses.
- The milestone section shows the fixed `open -> closed` lifecycle and the release section the fixed `planned -> released` lifecycle.
- The decision section shows `proposed`, `accepted`, `rejected`, `deprecated`, and `superseded` with the documented transitions.
- Every front-matter-backed document section shows the main `active -> archived` storage lifecycle and the custom statuses declared for that type; the UI mockup section shows `pending -> approved -> archived`.
- Backlog.md `docs` and `drafts` records and project configuration files are not described by the page.
- Each section provides a good description of its artifact on top of its lifecycle and existing status.
- Each section shows the artifact's effective `enabled` state, ID prefix, and storage folder; the task section also shows the configured task statuses, and each document section shows its declared custom statuses.
- A document type added by configuration is described by the shared document lifecycle and its configured prefix and folder, without requiring curated description text.
- Description text is curated static content shipped with the browser and does not depend on requirement files, record content, configuration, or an internet connection.
- Configuration values on this page are read-only; changing them is done through the browser configuration view (REQ-006.008).
