## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Why.** REQ-01.005 still states that IDs remain stable `across archive/restore cycles for tasks and milestones`, and its second acceptance criterion says `archiving and restoring a task or milestone`. The milestone lifecycle is fixed `open -> closed` (REQ-03.001, REQ-07.001) and `papyrus milestone close <id>` is its only transition (TASK-130, ADR-0022 decision 5); milestones are never archived, so REQ-01.005 describes a removed operation and contradicts REQ-03.001. REQ-03.001 traceability also still carries `BR-006 - milestone Command Behavior (needs revision: archive becomes close)` although BR-006 now documents the close-only lifecycle, so the note makes a settled rule look outstanding.

**What.** Correct REQ-01.005 so archive/restore ID stability covers tasks only, and remove the stale BR-006 revision note from REQ-03.001, then regenerate the requirement indexes. No behavior change.

**In scope.**
- REQ-01.005 Description: IDs remain stable across archive/restore cycles for tasks, and across archiving for documents; the sentence must not claim archive/restore for milestones and may note that milestones are not archived because they use `close`.
- REQ-01.005 acceptance criterion 2: state that archiving a document or archiving and restoring a task does not change its ID; documents have no restore command and milestones are never archived (REQ-03.001).
- REQ-01.005 traceability: cite REQ-03.001 for the milestone exclusion and keep the existing references.
- REQ-03.001 traceability: remove only the parenthetical `(needs revision: archive becomes close)` and keep `BR-006 - milestone Command Behavior`, because BR-006 now documents the close-only lifecycle and remains the valid trace.
- Regenerate `docs/requirements/business/index.html` and `docs/requirements/non-functional/index.html` with the `requirements-index-visualization` skill and its bundled `generate_index.sh`; report each `wrote ...` line and exit 0, and never hand-edit either index.

**Out of scope.** CLI behavior, code, tests, ADRs, specifications, business rules, the domain model, requirement IDs and criticality, and other requirements - including the similar stale notes on REQ-03.002 (BR-007), REQ-04.002 (BR-008), REQ-05.002 (BR-010), and REQ-05.009 (BR-016/BR-017), which this task does not touch.

**Assumptions.** This is a wording and traceability correction only. TASK-130 delivered the close-only milestone lifecycle and TASK-127 corrected the specification pages; they are the traceability context, not dependencies.
