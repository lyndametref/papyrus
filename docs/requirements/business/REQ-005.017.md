# REQ-005.017 View and List Document Records

## User Story

As a project contributor, I want to list and open the records of any document type so that I can find documentation and read it in context.

## Group

REQ-005 Project Documentation Management

## Criticality

Must have

## Description

Every document type declared in the project configuration is listable and viewable from the command line and from the browser. This requirement fixes what the list rows and the record content contain per document model; the shared chrome, layout, and action placement are owned by REQ-006.016 for lists and REQ-006.012 for single-record views.

**List.** A list shows one row per record. A row carries the record title and its labels in the title cell, the type's declared list slots, and the record's reference list only when the type's reference visibility is `visible`; when it is `hidden` the row carries no reference list, while labels still render. The content of the slots and the visibility value come from the type descriptor (REQ-007.002).

**GroupedMarkdown lists.** A list of a `GroupedMarkdown` type shows its group records and their members merged: group order first, then member order within each group. Member rows are read-only in the list (REQ-005.001).

**Record content.** For the Markdown models, a single-record view renders one section per declared field in field-sequence order, using the field's label as the section heading; a field with no value contributes no section, except that a required field with no stored value is rendered as an empty section. For `SingleHtmlMockup`, the view renders the fixed metadata block instead of field sections (REQ-005.008). The References disclosure is present on the single-record view of every model, whatever the reference visibility of its type.

**Out of scope in a view.** A record that is unknown, archived, or of a type that is not configured is not viewable: no command and no browser route returns it, and the browser shows the shared not-found page (REQ-005.007).

**Absence from lists.** Archived records appear in no list.

## Acceptance Criteria

- Every configured document type can be listed and viewed from the command line and from the browser.
- A list shows one row per record.
- A row carries the title and labels in the title cell and the type's declared list slots.
- A row carries the record's reference list when the type's reference visibility is `visible`, and no reference list when it is `hidden`.
- Labels render in the title cell whatever the reference visibility of the type.
- A `GroupedMarkdown` list shows group records and their members merged in group order, then member order within a group, with member rows read-only.
- A Markdown record view renders one section per declared field in field-sequence order, headed by the field label.
- A field with no value contributes no section, except a required field with no stored value, which renders as an empty section.
- A `SingleHtmlMockup` view renders the fixed metadata block instead of field sections.
- The References disclosure is present on the single-record view of every model, whatever the type's reference visibility.
- An unknown record, an archived record, and a record of a type that is not configured are not viewable and produce no list or view output.
- Archived records appear in no list.
- The shared list layout and the shared single-record layout follow REQ-006.016 and REQ-006.012.
