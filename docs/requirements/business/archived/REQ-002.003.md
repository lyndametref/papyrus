# REQ-002.003 List and Filter Tasks

> **Deprecated.** Superseded by REQ-002.002, which now covers viewing, listing, filtering, and readiness for tasks.

## User Story

As a project contributor, I want to find tasks by their attributes and text so that I can focus on relevant work.

## Group

REQ-002 Task and Board Management

## Criticality

Must have

## Description

The task list supports filtering by status, milestone, release, label, assignee, and text, limiting the number of results, and sorting by a selected field. A release filter includes tasks belonging to milestones assigned to that release. Watch mode keeps the list open and refreshes it on changes.

`--ready` restricts the list to unfinished tasks whose every dependency is resolved to the project's configured final task status. The final task status is the last entry of the configured task `statuses` list (REQ-001.002); it is not a separately configured key. A task is unfinished when its status is not that final status. Readiness is derived at read time from the stored `dependencies` front matter (REQ-005.010); no readiness field is stored and no data shape changes. A dependency that is missing, unknown, ambiguous, self-referential, part of a cycle, or not in the final status blocks the task (fail-closed). An archived dependency counts as resolved only when it is in the final status.

The task list is non-interactive: it prints plain text by default, there is no interactive mode, and there is no dedicated plain-output option. `--plain` is not an option of `papyrus task list`; passing it is a usage error. Output honors the global `--json` option (REQ-001.004). `--ready` may be combined with the other documented filters.

## Acceptance Criteria

- Each documented task-list filter restricts results to matching tasks.
- A release filter includes tasks on milestones assigned to that release.
- `--limit` caps the number of results and `--sort <field>` sorts by the requested field.
- `--watch` keeps the list open and refreshes it when changes occur.
- `--ready` restricts results to unfinished tasks whose every dependency is resolved to the configured final task status.
- A dependency that is missing, unknown, ambiguous, self-referential, cyclic, or not in the final status blocks its dependent task.
- An archived dependency counts as resolved only when it is in the final status.
- Readiness is derived at read time and is not stored in task front matter.
- `papyrus task list` has no interactive mode and prints plain text by default.
- `papyrus task list` accepts no `--plain` option; passing `--plain` is a usage error (exit code 2, REQ-001.004).
- Task-list output honors the global `--json` option (REQ-001.004).
- `--ready` may be combined with the other documented filters.
