# REQ-007.004 Define the Document Content Model

## User Story

As a project contributor, I want every document type to declare its document model and content fields so that a record's identifiers, fields, state, and commands stay consistent without per-type code.

## Group

REQ-007 Record Categories and Config-Defined Document Types

## Criticality

Must have

## Description

**One model per type.** Every document type declares exactly one document model in its configuration entry: `simple-record`, `grouped-record`, or `formatted-record`. An omitted `model` is `simple-record`, and an unknown value is rejected (REQ-007.002). Any configured type may declare any of the three models.

**simple-record** — one record per plain identifier, a Markdown body, and one field sequence, which may be empty (REQ-005.015).

**grouped-record** — a group record with a plain identifier, and member records whose dotted identifier names their group's sequence (REQ-001.005). The type declares a `group` and a `member` role, each with its own field sequence and independent order; it declares no top-level field sequence. The owning group is the reserved front-matter key `group`, written and maintained only by the engine; membership is immutable, and archiving or deleting a group changes no member (REQ-005.001).

**formatted-record** — one record per plain identifier with an HTML body and no field sequence. Its state lives in its HTML metadata comment with the fixed states `draft` and `approved`; it has no `status` verb, `edit --status approved` performs the `draft` to `approved` transition, and `archived` is a file position, not a state value (REQ-005.008).

**Field specifications.** A field declares a stable key, an optional body heading, a CLI option, a name and help text, a kind of `text`, `multiline`, or `list`, whether it is required, and the verbs on which it may be set (REQ-007.002). A required field must be supplied on create and may be changed but not cleared on edit; an optional field may be supplied or cleared. A field's position in its sequence is its order in the record body, in the command line and help, and in the browser form. Adding or changing a field is a configuration file edit, not a code change.

**What the model fixes.** The document model determines the identifier shape, the number of records a type has, the body format, where state is stored, whether role field sets apply, and the verb family (REQ-007.003). It does not change the status model of the document category (REQ-007.001).

**Configuration is data, never code.** Configuration declares models, fields, and presentation facts only. It is never executable: no template, expression, script, or code path is read from it. Content changes are computed by the engine as operations that set a front-matter key, set or clear a body section, set the heading title, or change model-specific group and metadata state, and a single writer applies them atomically (REQ-005.011). No per-type module, table, or code path defines a document type's model, fields, or verbs.

## Acceptance Criteria

- Every document type declares exactly one document model: `simple-record`, `grouped-record`, or `formatted-record`.
- An omitted `model` is `simple-record`, an unknown value is rejected, and any configured type may declare any of the three models.
- A `simple-record` type has one record per plain identifier, a Markdown body, and one field sequence that may be empty.
- A `grouped-record` type has a group record with a plain identifier and member records with dotted identifiers naming their group's sequence.
- A `grouped-record` type declares a `group` and a `member` role with independent field order and no top-level field sequence.
- The `group` link of a member record is reserved and engine-owned, membership is immutable, and archiving or deleting a group changes no member.
- A `formatted-record` type has one record per plain identifier, an HTML body, and no field sequence.
- A `formatted-record` record keeps its state in its HTML metadata with the fixed `draft` and `approved` states, has no `status` verb, and `archive` moves the file without changing the state.
- A field declares a key, an optional heading, a kind of `text`, `multiline`, or `list`, a required flag, and verbs from `create` and `edit`; without a heading the field is metadata-only and stored under its key.
- A required field must be supplied on create and may be changed but not cleared on edit; an optional field may be supplied or cleared.
- Field sequence position governs record body order, command-line option and help order, and browser form order.
- Adding or changing a field is a configuration file edit, not a code change.
- The document model determines identifier shape, record count, body format, state storage, whether roles apply, and the verb family, and changes no document status rule.
- Configuration declares models, fields, and presentation facts only and is never executable.
- Content changes are applied by a single writer from engine-computed operations, and a patch that changes nothing writes no file.
- No per-type module, table, or code path defines a document type's model, fields, or verbs.
