# REQ-004.001 Create and Inspect Decisions

## User Story

As a project decision-maker, I want to create and inspect decisions with context and consequences so that decisions are recorded for future reference.

## Group

REQ-004 Decision Records

## Criticality

Must have

## Description

The user can create and list decisions, optionally filtering by type, and view a decision. A decision records a title, decision type, decision, context, and consequences. Built-in types are `adr` and `bdr`; additional types may be configured. Decisions may reference zero or more business and non-functional requirements. Records follow the Nygard ADR template and the fixed status vocabulary of the decision category (REQ-007.001): `proposed`, `accepted`, `rejected`, `deprecated`, and `superseded`. `rejected` is the canonical term; `refused` is not a Papyrus status. A decision's status stays in the document core and its type is derived from the record ID prefix (REQ-005.010).

## Acceptance Criteria

- A decision can be created with the documented title, type, decision, context, and consequences fields.
- The default decision type is `adr`; `adr` and `bdr` are the built-in types.
- Decisions can be listed and viewed; listing can be filtered by type.
- Decision records expose the documented Nygard fields and exactly these status values: `proposed`, `accepted`, `rejected`, `deprecated`, and `superseded`.
- `refused` is not accepted as a decision status.
- Status transitions are proposed to accepted or rejected, and accepted to deprecated or superseded.
- A decision may reference zero or more business requirements and zero or more non-functional requirements.
- Decision status is not configurable.
