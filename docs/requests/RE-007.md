# RE-007 Support multiline input in papyrus create and update commands

## Description
Bug: `papyrus <type> create` and `papyrus <type> update` reject multiline input because single-line validation rejects embedded newlines. Users need a supported way to pass multiline text (for example description, body, decision, context, consequences) without relying on `--editor`.

## Items

### Item 1
- Statement: Add a supported multiline-input path to Papyrus create and update commands, so users can supply multiline field values directly (for example via a file flag, stdin, or a documented escape mechanism) instead of only through `--editor`.
- Requester and context: user, 2026-11-18, Papyrus CLI usability.
- Theme: CLI input handling
- Affected area: document and backlog create/update commands
- Open questions: none (resolved 2026-11-18: multiline input via stdin; body/content fields only; identifiers and titles remain single-line).
- References: none
