## Findings

### High

H-1 The retained release artifact predates the audited tree.
Evidence: the packaged binary is sha256 430a6e538fcdc9ccc3b59d7c4b8ab9b53fc0410016b5b6224777ce9b0671e2ba and contains the literal "DEBUG closed"; the 1.0.0-rc.1 packaged binary is byte-identical. A release build from HEAD 103604e is sha256 d519577bfddb86da312032f9ab43c8af9be538fa727e13b0369ed6732fd55a6a and contains no "DEBUG closed". git diff --stat cceed99..HEAD is exactly TASK-289: the src/browser/mod.rs debug-line removal, docs/packaging.md, and backlog/tasks/TASK-289.md. docs/packaging.md line 69 states the package was built from cceed99 (merged at 440b9fe), and it was not rebuilt after the TASK-289 source change. The artifact therefore does not correspond to the audited source, and the recorded artifact sha256 e59150d011582fa57f8e9bc13e7e36460019d0886132c188bd8a4e20ac3312b6 no longer represents HEAD.
Location: builds/1.0.0/.build/papyrus/papyrus_1.0.0_amd64.deb; builds/1.0.0-rc.1/.build/papyrus/papyrus_1.0.0-rc.1_amd64.deb; src/browser/mod.rs; docs/packaging.md:69.
Recommendation: rebuild the single 1.0.0 package from HEAD with scripts/build-package.sh --version 1.0.0 --out builds/1.0.0/.build/papyrus --force; re-verify metadata, inventory, install and sha256; record the new sha256 and HEAD commit in docs/packaging.md and the TASK-289 evidence. Rebuild or discard the RC so the evidence binary matches HEAD.

### Medium

M-1 The configuration YAML budget is bypassed by config set and config unset.
Evidence: read_raw_config applies validate_yaml_input (src/commands.rs:66-68), but config_set (src/commands.rs:323-325) and config_unset (src/commands.rs:416-418) call std::fs::read_to_string and yaml_serde::from_str directly. Probe: a configuration containing "statuses: &s" is rejected by "papyrus config list" with "configuration must not contain YAML anchors or aliases", but "papyrus config set project_name Renamed" exits 0 and rewrites the file. The phase-2 load error is discarded with .ok() at src/lib.rs:115, so the tolerant path reaches the unguarded read.
Location: src/commands.rs:323-325 and 416-418; src/lib.rs:114-116.
Recommendation: route every configuration read through read_raw_config, or apply validate_yaml_input before parsing, and keep the phase-2 load error for the config subcommand.

### Low

L-1 The anchor and alias scanner has lexical gaps and a false positive.
Evidence: "anchor: !!seq &x [1, 2, 3]" with a "? *x" explicit key is accepted; the command fails later on the schema, not on the YAML limit, because the scanner does not treat a tag or the "?" explicit-key indicator as a node start (src/config.rs:115-158). A valid block scalar with a header comment ("project_name: | # name" followed by "  * Rock") is rejected because block_scalar_parent_indent requires the indicator to be the last value token (src/config.rs:161-207). The parser's own alias cap still bounds expansion, so impact is limited, but the stated reject-anchors-or-aliases contract is incomplete.
Location: src/config.rs:92-207.
Recommendation: use the YAML parser tokens or events, or extend the scanner for tags, explicit keys, and header comments; otherwise document the scanner as best-effort with the parser cap as the control.

L-2 The size caps are applied after the whole file is read.
Evidence: read_raw_config calls std::fs::read_to_string (src/commands.rs:66) and then checks MAX_CONFIG_YAML_BYTES; record front matter is parsed from an already-read record. An oversized file is fully allocated before rejection, so the cap bounds parsing but not the read.
Location: src/commands.rs:66-68; src/record/frontmatter.rs parse_yaml.
Recommendation: check the file length or use a bounded reader before read_to_string, or document the cap as a parse budget only.

L-3 destination_occupied is duplicated and its error handling is inconsistent.
Evidence: the same helper is defined at src/task.rs:1710 and src/milestone.rs:831, and src/record/relocate.rs:161-170 performs the symlink_metadata match inline. task.rs and milestone.rs treat any metadata error as "not occupied", while relocate.rs returns a Validation error for non-NotFound errors.
Location: src/task.rs:1710; src/milestone.rs:831; src/record/relocate.rs:161-170.
Recommendation: move one helper to the record store layer and use one error policy.

L-4 ADR-044 decision 8 is stale.
Evidence: decision 8 and the Consequences section say the warning-text follow-up is "not implemented by this ADR" and "outstanding", but TASK-316 implemented it at src/browser/mod.rs:340 and in the README. The decision record should reflect the implemented state or mark the follow-up closed.
Location: decisions/ADR-044-non-loopback-browser-binding-is-an-explicit-unauthenticated-risk.md:33,48; src/browser/mod.rs:340; README.md.

L-5 Containment is checked but the canonical path is discarded.
Evidence: contained_config_path returns a canonical PathBuf, but the shadowed binding is local (src/lib.rs:114-115), and cli::dispatch receives the raw sanitized path (src/lib.rs:167). The is_config and help/version branches also call config_path.exists() before containment (src/lib.rs:114,126). Reads are gated on the load path, but later config set and config unset reads use the raw path, and the containment check is not uniformly first.
Location: src/lib.rs:72-84,114-116,126,167.
Recommendation: pass the canonical contained path into dispatch and move the containment check before the existence probe where possible.

L-6 The release build runs twice.
Evidence: build-package.sh runs cargo build --release --locked (line 108) and then calls build-deb.sh, which runs it again (line 236) because the direct assembly path now always rebuilds.
Location: scripts/build-package.sh:108; scripts/build-deb.sh:236.
Recommendation: let one layer own the rebuild, or pass an explicit already-built flag from the entry point.
